# Главная страница

По умолчанию `https://example.org/` показывает локальную страницу сервера. «Войти» открывает `https://web.example.org/#/login`, «Зарегистрироваться» — `https://web.example.org/#/register`: клиент начинает штатную авторизацию MAS с возвратом в Element. Пароль и настроенные дополнительные способы входа предлагает сама форма авторизации. Кнопка регистрации скрыта при `OPEN_REGISTRATION=false`. При регистрации по приглашению код вводят в форме MAS, а не в адрес страницы. Лендинг не показывает пароль администратора или первый токен.

Для подключения приложения Matrix лендинг показывает основной домен сервера
(например, `example.org`); адрес клиентского API определяется через Matrix discovery.

Внизу стандартной страницы кнопка «Подключить свой сервер» открывает репозиторий
Misbot. Её адрес задаётся один раз в поле `homepage_setup_url` файла
[release.json](release.json). Следующий комплект Misbot может менять этот адрес;
при обновлении стандартный лендинг пересоздаётся с новой ссылкой. Это относится
и к подключённому Compose-серверу. Его индивидуальный шаблон `site-template`
сохраняется; добавить эту ссылку в такой шаблон можно через `@@SETUPURL@@`.

## CLI и SSH UI

```bash
sudo misbot homepage show
sudo misbot homepage check --mode landing --name 'Наш сервер' --description 'Общение команды'
sudo misbot homepage apply --mode landing --name 'Наш сервер' --description 'Общение команды'
sudo misbot homepage apply --mode element
sudo misbot homepage check --mode external --url https://community.example.net/
sudo misbot homepage apply --mode external --url https://community.example.net/
sudo misbot homepage apply --mode landing
```

Все операции требуют root и выбранной принадлежащей Misbot установки. Другой каталог: `sudo misbot --directory '/opt/My Matrix' homepage show`. В `sudo misbot ui` выберите «главная страница»: можно изменить отдельное поле, увидеть итог и подтвердить применение. Отмена до подтверждения сохраняет действующий сайт.

`check` проверяет общую схему и конфигурацию Caddy без применения. `apply` сохраняет приватную прежнюю конфигурацию, публикует новые файлы, пересоздаёт только Caddy и проверяет главную, Matrix/Misbot discovery и Matrix client API с нормальной проверкой HTTPS. Возможен короткий перерыв HTTPS; БД, медиа, identity, OAuth callbacks, боты и политика федерации не изменяются. Внешний сайт не проверяется и не получает параметры исходного URL. Синтаксически корректный URL не доказывает доступность или содержимое чужого сайта.
При выключенном Misbot API проверка принимает только штатный ответ
`503` с `code: api_disabled` на Misbot discovery; Matrix discovery и client API
по-прежнему должны отвечать успешно. Это относится также к recover и rollback.

Перенаправление временное, HTTP 302, с `Cache-Control: no-store`. Для внешней цели требуется HTTPS без credentials, управляющих символов и нестандартного порта. Управляемые домены установки запрещены как внешняя цель; Element выбирают отдельным режимом. Циклы, созданные впоследствии владельцем чужого сайта, нельзя обнаружить локальной валидацией.
Если у цели нет собственного fragment, Location заканчивается явным пустым `#`:
браузер не наследует fragment исходной страницы, который мог содержать OAuth token.
Исходный query также не переносится.

## Ручная конфигурация

Необязательный `settings/site.env`, root 0600, использует [общий загрузчик](configuration.md). Его отсутствие означает defaults; env не исполняется. Пример: [site.env.example](configuration-examples/site.env.example).

| Поле | Формат/default | Влияние |
| --- | --- | --- |
| `HOMEPAGE_MODE` | `landing` (default), `element`, `external` | Только главная и прокси |
| `HOMEPAGE_URL` | HTTPS URL; обязателен для external, иначе пусто | Фиксированная цель без исходных query/fragment |
| `SITE_NAME` | Текст до 120 символов; пусто — домен | Заголовок |
| `SITE_DESCRIPTION` | Текст до 1000 символов; «Общайтесь в своём пространстве Matrix.» | Описание |
| `SITE_SUPPORT_URL` | Необязательный HTTPS URL; пусто | Ссылка поддержки скрыта при пустом поле |

Тексты экранируются как текст; HTML/JavaScript не выполняется. Лендинг использует локальный CSS и системный шрифт, без аналитики, CDN и JavaScript. Вручную: `sudo misbot config validate`, затем `sudo misbot config apply` и `sudo misbot check`. Для изменения только сайта используйте `homepage apply`, чтобы не перезапускать другие службы.

## Ошибка и продолжение

Изменение сайта недоступно, если первоначальная установка ещё остановлена
на подготовке ботов и HTTPS-службы не созданы. Сначала завершите запуск сервера.
Если прежний комплект уже оставил checkpoint сайта в таком состоянии,
«Вернуть прежний сайт» восстанавливает сохранённые файлы без запуска служб;
проверка HTTPS откладывается до завершения установки. Это исключение относится
только к незавершённой обычной установке без ранее созданного HTTPS-прокси.
На установленном сервере и в `existing-compose` восстановление по-прежнему
требует проверки действующих маршрутов.

Если установленный комплект ещё содержит этот дефект, выполните откат сайта
из доверенного распакованного исправленного комплекта:
`sudo python3 homepage.py --directory /opt/matrix-stack rollback`.
Команда использует сохранённый checkpoint, проверку принадлежности установки
и общую блокировку. Затем примените исправленный комплект штатным обновлением
и продолжите запуск в том же каталоге; ключи и данные не удаляйте.

При ошибке обычного применения backend пытается вернуть прежние настройки и проверить их. После прерывания или неудачного rollback checkpoint остаётся в `homepage-transition.json`, приватные файлы — в `stages/homepage/`. Общая блокировка запрещает параллельные изменения; не удаляйте lock или checkpoint.

```bash
sudo misbot status
sudo misbot homepage recover
# либо вернуть прежнюю конфигурацию:
sudo misbot homepage rollback
```

DNS/TLS/timeout при проверке своего домена означает, что результат по HTTPS не подтверждён; проверьте DNS, сертификат, порты и доступность прокси. Недоступность выбранного внешнего сайта исправляется у владельца того сайта либо выбором `landing`. Повторный `recover` после успеха безопасен. На лендинге нет конфигурации, журналов или реквизитов. Пути Matrix API, MAS/OAuth, RTC/TURN, discovery и `/_misbot/v1/exchange` сохраняют своё назначение во всех режимах.

Настоящий браузерный вход, регистрация, возвращение в клиент и дополнительные OAuth-провайдеры проверяются отдельно от HTTP routing. Восстановление из копии возвращает настройки сайта и данные на момент копии, без обещания сохранить более поздние изменения.
