# Конфигурация и SSH-мастер Misbot 1.2.0

Руководство объясняет настройки обычной установки Misbot: как пройти мастер,
подготовить файлы вручную и изменить работающий сервер. Для первого развёртывания
сначала подготовьте VPS и DNS по [инструкции установки](README.md).
Для подключённого готового стека действуют
[другие настройки и ограничения](existing-compose.md).

- [SSH-мастер](#ssh-мастер) — настройка с вопросами и сохранением черновика.
- [Ручное создание](#создание-установки-через-cli) — `config init`, файлы и первый запуск.
- [Изменение работающего сервера](#изменение-работающего-сервера) — проверка и применение.
- [Поля](#поля) — справочник имён, значений по умолчанию и условий использования.

## SSH-мастер

В распакованном комплекте: `sudo python3 misbot.py ui`. После установки:
`sudo misbot ui` или `sudo misbot` в TTY. Для другого каталога добавьте
`--directory '/opt/Matrix Test'`. В non-TTY используйте обычный CLI;
явный запуск меню возвращает код 2 и подсказку `ssh -t USER@HOST`.

В обычном SSH-терминале мастер открывается на весь экран, использует ширину
окна и обновляет экран при переходе между шагами. После выхода восстанавливается
прежний экран терминала. Итог установки и результаты операций остаются до Enter.
Ввод — номера и Enter; команды `назад`, `отмена`, `сохранить и выйти` сохраняются.
`sudo misbot ui --plain` включает последовательный вывод без оформления.
Без Rich, при `TERM=dumb` или `NO_COLOR` полноэкранный режим не включается.
Узкое окно использует компактный список; следующий экран учитывает новый размер.
Показывает этап, выбранную установку и описание поля. Enter сохраняет предложенное значение
или уже настроенный секрет; секрет вводится без эха. `назад` возвращает шаг,
`отмена` прекращает ввод, `сохранить и выйти` сохраняет приватный черновик.
После ошибки Enter или `повторить` запускает текущий шаг снова. Неизвестный
ответ оставляет запрос открытым. При прерывании операции мастер ждёт остановки
backend перед возвращением к меню; повторное прерывание не отменяет ожидание.
Повтор `ui` продолжает черновик, сохраняя внутренние ключи. Ctrl+C во время
операции передаётся backend; дождитесь завершения, затем следуйте `misbot status`.
При потере SSH дочерняя операция может ещё завершаться: busy не обходят удалением lock.
При выборе другого каталога установки черновик переносится к этому каталогу:
команда продолжения с `--directory` найдёт настройки. Если для каталога уже
есть другой черновик, мастер предлагает открыть его отдельно и сохраняет оба.

После прерывания первоначального запуска мастер продолжает `start`, затем
проверку. Уже созданные базы, действующие настройки и ключи сохраняются;
черновик поверх них не применяется. `назад` на этих этапах открывает меню
управления. Повторный `init` не нужен.

Мастер проверяет Linux amd64/systemd, память, диск, DNS/CAA, порты и маршруты.
Если отсутствуют зависимости: `sudo apt-get update`, затем
`sudo apt-get install -y python3 python3-yaml dnsutils iproute2` и повтор `ui`.
Мастер сначала проверяет DNS всех управляемых имён и показывает готовые записи,
отсутствующие или неправильные A, лишние AAAA и недоступность DNS.
Создавать уже готовые записи не нужно. При несоответствиях следующий проход
начинается через десять секунд после ответов предыдущего; медленные запросы
не накладываются друг на друга. Статусы обновляются автоматически. `b` возвращает
назад, `q` сохраняет черновик и выходит; доступны также обычные текстовые команды.
При пустом публичном IPv4 и отсутствии единственного A основного домена мастер
просит адрес из панели VPS. Отключите DNS proxy; порты указаны в [README](README.md).

В итоге поля пронумерованы; в небольшом окне доступны страницы `>` и `<`.
Введите номер, чтобы изменить поле. `назад` внутри редактора возвращает к итогу.
Enter выбирает **сохранить и выйти**; только `применить` начинает установку.
После изменения домена, MAS или IPv4 DNS проверяется повторно до создания установки.
Имя административного бота можно выбрать здесь до создания аккаунта.
Срок приглашений используется по умолчанию и изменяется после установки
в разделе **Настройки сервера**; текущие приглашения не продлеваются.

Неинтерактивные операции показывают один индикатор над ограниченным окном
вывода. Он движется и при ожидании без новых строк. Пароли и коды по-прежнему
показываются только отдельным подтверждённым запросом.

Просмотр приватного черновика без его значений:
`sudo python3 misbot.py config draft show --directory /opt/matrix-stack`.
Удаление только текущего черновика:
`sudo python3 misbot.py config draft reset --directory /opt/matrix-stack --confirm discard-draft`.
Команды доступны до создания каталога установки. Данные сервера, ключи,
checkpoints и отдельно сохранённые прежние черновики остаются.
Если системный runtime удалён, выполняйте эти команды из проверенного комплекта.

Поля проверяются перед сохранением. При неверном вводе мастер объясняет допустимый
формат и повторяет вопрос; прежнее значение сохраняется. Для домена с нелатинскими
символами показываются читаемое имя и ASCII-адрес для DNS (`xn--…`); требуется
отдельное подтверждение. Enter отменяет такое подтверждение. Невидимые символы,
URL, IP-адрес, путь и порт в поле домена не допускаются.
Старые черновики проверяются перед DNS и применением. Подтверждённое имя
запоминается в приватном черновике, поэтому повторного вопроса нет.

Каталог установки задаётся абсолютным путём: латинские буквы, цифры, пробелы,
точки, дефисы и подчёркивания. Обычный файл, ссылка, переход `..` и чужой непустой
каталог не подходят. Вопросы с вариантами ответа принимают только показанные
варианты. Поля S3 проверяются до сетевой диагностики; расписание — через
`systemd-analyze calendar`. Ключ внешних копий хранится вне каталога установки;
существующий ключ сохраняется и должен иметь приватные права и длину 32 байта.
Для endpoint S3 и расписания доступно `/очистить`: AWS endpoint для указанного
региона и ручные копии соответственно. Явный отказ от Google/Telegram или
внешних копий убирает выбранную функцию из черновика первоначальной установки.

При ошибке DNS команда `назад` возвращает к домену и каталогу, минуя автоматическую
проверку системы. Исправьте имя, затем повторите проверку DNS. Пока инициализация
не выполнена, для продолжения используется `sudo python3 misbot.py ui` из
распакованного комплекта; команды `misbot status` ещё может не быть.

## Создание установки через CLI

Если используете мастер, этот раздел можно пропустить. Из проверенного
распакованного комплекта создайте новую установку в пустом каталоге:

```bash
sudo python3 misbot.py --directory /opt/matrix-stack config init --domain example.org
```

`init` создаёт настройки и приватные внутренние ключи, копирует runtime и
регистрирует системную команду. Чат ещё не запущен. Обычная CLI-инициализация
выбирает локальную PostgreSQL и локальные медиа. Заполните нужные файлы из
таблицы ниже; для внешних ресурсов сначала подготовьте их доступы и прочтите
[руководство хранилищ](storage.md). Парольный вход без OAuth не требует `auth.env`.

```bash
sudo nano /opt/matrix-stack/settings/server.env
sudo misbot config validate
sudo misbot config preflight
sudo misbot start
sudo misbot check
```

В примерах замените домен и путь своими значениями. При ошибке исправьте
названное поле или сетевое условие и повторите проверку. После частичного
`start` сначала проверьте `sudo misbot status`: незавершённая операция может
потребовать своего recovery. Не создавайте новую identity ради повтора запуска.

## Единственный источник настроек

Формат конфигурации **2** отделён от версии продукта **1.2.0**.
Вымышленные примеры находятся в `configuration-examples/*.env.example`.
Копируйте только нужную область в `settings/`, замените её значения и установите
`chmod 600` до валидации. Имена и значения по умолчанию совпадают со схемой мастера.
В каталоге установки:

| Файл | Назначение | Когда нужен |
|---|---|---|
| `settings/server.env` | Matrix-домен, отдельный домен MAS, IPv4, email, режимы медиа/БД | Всегда |
| `settings/policy.env` | Сеть, федерация, регистрация, приглашения и размер вложений | Если значения по умолчанию изменены |
| `settings/media-s3.env` | Шесть параметров S3 медиа | Выбраны S3-медиа или сохранены параметры подключения |
| `settings/auth.env` | Google/Telegram OIDC и Telegram egress | Выбран соответствующий провайдер |
| `settings/database.env` | Существующий внешний connector PostgreSQL | Используется дополнительная внешняя БД |
| `settings/backup.env` | Отдельный S3 профиль, recovery key и расписание | Настроены внешние копии |
| `settings/site.env` | Режим главной страницы, название, описание и поддержка | Если значения по умолчанию изменены |
| `secrets/` | Автоматически созданные внутренние пароли и токены | Backend; вручную не редактировать |
| `config/`, `compose.yaml`, `mas-proxy.env` | Сгенерированные рабочие файлы | Не являются пользовательскими шаблонами |

`FEDERATION_AUTO_ACCEPT` в policy.env: логическое значение `true`/`false`, по умолчанию `false`.
Включает только приём комнат от точного bot MXID одобренного connected peer;
не меняет allowlist и права участников. Применяется сразу backend при проверке
приглашения. Значение задаётся в `settings/policy.env` через общую конфигурацию.
Остальные [операции федерации](federation.md) используют тот же загрузчик.

Каталог `settings` — root:root 0700, файлы — root:root 0600, обычные файлы,
без symlink/hardlink. Env читается буквально как UTF-8 `KEY=value`: без `export`,
shell-кода, подстановок и комментариев после значения. Внешние парные кавычки
снимаются; символы внутри остаются буквальными. Не выполняйте `source`.
Каждое поле принадлежит одной области; чужие, неизвестные и повторяющиеся поля
отвергаются. Defaults заполняет общая модель; файлы не перекрывают друг друга.
Профиль backup имеет собственные S3-поля и не перекрывает media.

### Размер вложений

По умолчанию можно загрузить одно вложение размером до **256 МиБ**
(268 435 456 байт). Лимит общий для файлов, фотографий и видео, при локальном
хранении и S3. В обычном мастере установки отдельного вопроса о нём нет.

Чтобы изменить лимит, откройте `sudo misbot ui` → **Настройки сервера** →
**Максимальный размер вложения, МиБ**. Либо задайте в `settings/policy.env`:

```dotenv
MAX_UPLOAD_SIZE_MIB=512
```

Допустимо целое число от 1 до 65536, без единиц в значении; 1 МиБ = 1 048 576 байт.
После ручного редактирования выполните `sudo misbot config validate`, затем
`sudo misbot config apply`. Применение создаёт согласованную копию и может кратко
перезапустить службы. Сохранённые вложения не удаляются.

При обновлении обычной установки без этого поля применяется новый лимит
256 МиБ. Явно заданное значение сохраняется, в том числе в старом `settings.env`.
У подключённого `existing-compose` стека лимит меняют его собственными средствами.
Файл `config/homeserver.yaml` генерируется автоматически; редактировать его не нужно.

### Отдельный домен MAS

`MAS_DOMAIN` в `settings/server.env` задаёт hostname MAS независимо от `DOMAIN`:

```dotenv
DOMAIN=example.org
MAS_DOMAIN=auth.example.net
```

Пустое поле сохраняет значение по умолчанию `mas.<DOMAIN>`. Возможны общий адрес с основным
доменом или `matrix.<DOMAIN>`: прокси сохраняет Matrix API и маршруты авторизации.
Задайте домен до первого запуска баз. После этого issuer неизменяем: попытка
смены поля отклоняется до генерации runtime и остановки служб. Для старой установки
с нестандартным issuer впишите его существующий hostname; URL, ключи и OAuth-привязки
должны совпадать с сохранённой конфигурацией.

Этот параметр именует локальный MAS; его DNS должен вести на этот VPS.
Он не подключает сервер к MAS другого homeserver. В OAuth-приложениях используйте
`https://<MAS_DOMAIN>/upstream/callback/<provider-id>` и соответствующий HTTPS origin.
Не переносите существующие credentials в чат или Git.

## Изменение работающего сервера

Редактируйте файлы в `settings/`, проверяйте их, затем применяйте. Сначала
проверьте `sudo misbot status` и завершите известные незавершённые операции.
Домен Matrix и уже запущенного MAS этим способом изменить нельзя.

```bash
sudo nano /opt/matrix-stack/settings/server.env
sudo misbot config validate
sudo misbot config apply
sudo misbot check
```

`validate` не подключается к Docker или внешним ресурсам и не выводит значения.
Его JSON содержит `stage`, `status`, `format`; при ошибке схемы — безопасные
`code`, `file`, `field`, `explanation`, `next_actions`. Exit code: 0 — готово,
2 — ошибка ввода, 1 — pending/runtime; прерывание конфигурационной операции — 130.
`apply` проверяет модель и неизменяемую identity. На сервере с уже
инициализированными БД он создаёт согласованную копию, проверяет восстановление
включённых БД и вызывает запуск. До инициализации БД сохраняется только снимок
настроек. `config generate` тоже изменяет файлы и подготавливает образы,
хотя не перезапускает службы; для проверки без применения нужен `validate`.
При внешнем MAS его состояние сохраняют отдельно по [руководству копий](backup.md#копии-при-внешнем-mas).
Возможна короткая остановка.
Если ввод неверен, сообщение называет файл/поле и способ повторной проверки;
неверные значения не публикуются мастером. После ручного редактирования до
успешной валидации не запускайте `apply`. Identity и установленное хранилище
меняются только отдельными поддерживаемыми операциями; DOMAIN/server_name
неизменяемы. Смена credentials — [отдельные операции](credentials.md).
Меню настроек разрешает только обычные изменяемые параметры; отмена сохраняет
действующую конфигурацию. При неудаче его применения возвращается checkpoint.

## Внешний MAS

По умолчанию `MAS_MODE=local`: Misbot устанавливает MAS на этот же VPS, а адрес
входа — `mas.<DOMAIN>`. `MAS_DOMAIN` задаёт другой домен для этой локальной службы.

`MAS_MODE=external` подключает уже работающий MAS, заранее настроенный именно
для этого Matrix-сервера. В мастере выберите «Подключить уже работающий внешний
MAS» и введите его домен, общий ключ и реквизиты управляющего приложения.
Пароли и ключи вводятся скрыто. Запуск сначала проверяет HTTPS и управляющее
приложение MAS, затем поднимает публичный HTTPS Matrix для связи в обе стороны.
Уже существующий администратор `matrix-admin` сохраняет прежний пароль; Misbot
его не заменяет и не выдаёт новый пароль за действующий. Адрес входа и общий
ключ после первого запуска менять нельзя. Для настройки через приватный `settings/server.env`:

- `MAS_DOMAIN` — отдельный HTTPS-домен внешнего MAS без схемы и пути;
- `MAS_PUBLIC_IP` — необязательный ожидаемый IPv4 его A-записи;
- `MAS_SHARED_SECRET` — значение `matrix.secret` внешнего MAS;
- `MAS_CLIENT_ID` и `MAS_CLIENT_SECRET` — приложение внешнего MAS с доступом
  к `urn:mas:admin`, разрешённое в его `policy.data.admin_clients`.

На внешнем MAS должны совпадать `matrix.homeserver` и `DOMAIN`; адрес Synapse
задаётся как `https://matrix.<DOMAIN>` и должен быть доступен серверу MAS.
Совпадающий общий ключ требуется для связи MAS и Synapse. Регистрация должна
требовать приглашение: `account.password_registration_token_required=true`;
для OAuth-провайдеров также задайте `registration_token_required=true`.
Для первой установки имена `referral-bot`, `server-guide` и выбранное имя
административного бота должны быть свободны. Перенос прежней установки Misbot
выполняйте восстановлением копии с её сохранёнными сессиями и ключами ботов.
Google, Telegram и другие способы входа настраиваются на внешнем MAS; локальные
`GOOGLE_*`, `TELEGRAM_*` и `SOCKS5_CONFIG` в этом режиме не используются и
должны оставаться пустыми. Подключение проверяется
до первого запуска; уже действующий сервер на другой адрес MAS не переводится.
[Официальная настройка связи MAS и Synapse](https://element-hq.github.io/matrix-authentication-service/setup/homeserver.html).

DNS внешнего MAS сохраняет адрес его собственного сервера; этот адрес может
отличаться от IPv4 VPS Matrix. Сертификаты и данные внешнего MAS управляются
отдельно. Misbot не устанавливает его, не меняет его OAuth-провайдеров и не
удаляет его базы или ключи. Локальные копии Misbot не заменяют отдельную
резервную копию внешнего MAS. Перед восстановлением нужен тот же доступный MAS
с сохранёнными пользователями, сессиями устройств и ключами; активация требует
отдельного подтверждения `--external-mas-confirm preserved-state`. Подробнее —
[копии при внешнем MAS](backup.md#копии-при-внешнем-mas).

## Миграция и восстановление

Старый `settings.env` поддерживается без автоматической ротации. Сначала
обновите runtime через `misbot update apply --source /root/matrix-installer`,
затем выполните:

```bash
sudo misbot config validate
sudo misbot config migrate
sudo misbot config validate
sudo misbot status
```

Миграция проверяет принадлежность, immutable домен, pending состояния и схему;
сохраняет исходный файл приватно в `stages/configuration/ID/previous/settings.env`;
готовит полный новый набор, фиксирует `configuration-transition.json`, публикует
файлы, проверяет весь набор и удаляет старый действующий `settings.env`.
Пароли, ключи, БД, аккаунты, медиа и bot checkpoints не меняются.
Успех определяется проверкой всего набора. Во время незавершённой публикации
обычные операции отказываются читать настройки; все читатели используют общий lock.

После сбоя: `sudo misbot config recover`; для возврата приватной исходной копии
незавершённой публикации: `sudo misbot config rollback`. Повтор `migrate` после
успеха безопасен. При неизвестных полях миграция останавливается, сохранив файл;
разберите значение приватно, не удаляйте его без выяснения назначения.
После успеха редактируют только `settings/`; checkpoint остаётся для восстановления.

## S3 и внешние копии

Мастер использует [тот же диагностический backend](cli.md), включая безопасный
probe/cleanup. При отказе доступны исправление, повтор, локальные медиа до
подключения S3 или сохранение черновика. Уже установленный S3 не переключается
на пустое локальное хранилище. Позднее подключение переносит существующие файлы:

```bash
sudo misbot storage s3 check --config /root/misbot-s3.env --purpose media
sudo misbot storage s3 connect --config /root/misbot-s3.env
```

Внешние копии можно явно отложить. Это не подтверждает защиту от потери VPS.
Мастер хранит отдельный профиль в `settings/backup.env`; диагностика с
`--purpose backup`, внешние копии и таймер читают его через общую схему. Recovery key
должен находиться вне каталога установки, иметь приватные права; сохраните его
в защищённом независимом месте. Команды ручной проверки/применения расписания
даны в [инструкции копий](backup.md). Смена хранилища и смена credentials отдельны.

## Администратор и первый токен

При локальном MAS backend автоматически создаёт `@matrix-admin:DOMAIN` с
сохранённым паролем. При внешнем MAS уже существующий администратор сохраняет
прежний пароль; Misbot не выдаёт новый вместо него. Веб-панель:
`https://admin.DOMAIN`, чат: `https://web.DOMAIN`.
Локальные сохранённые реквизиты: `secrets/admin-access.json`.
Просмотр в root TTY: `sudo misbot credentials admin show`.
Смена: `misbot credentials admin set --help` (приватный файл, без пароля в argv).

После успешного запуска мастер подготавливает первый код приглашения на
**одного обычного** пользователя, без административных прав. Технически это
регистрационный токен MAS. По умолчанию он действует **604800 секунд / 7 дней**;
`INVITATION_LIFETIME_SECONDS` изменяет срок будущей выдачи. Создание администратора
не расходует приглашение. На экране завершения показывается состояние,
а сам код — только по отдельному запросу в терминале. Он не включается
в URL, JSON status или общие журналы; хранится приватно в
`secrets/first-registration.json`.

```bash
sudo misbot users invitation ensure  # создать или продолжить то же приглашение
sudo misbot users invitation status  # valid, used, expired, revoked, pending/absent
sudo misbot users invitation show    # только root TTY, секрет не для журналов
sudo misbot users invitation revoke
sudo misbot users invitation new     # явная замена после отзыва прежнего
```

Повтор `ensure` и завершение первоначального мастера сохраняют тот же код,
включая использованный, истёкший и отозванный. В меню **Пользователи и приглашения →
Пригласить пользователя** после подтверждения действующий код сохраняется,
а использованный, истёкший или отозванный заменяется через `new`. Потеря ответа
создания восстанавливается поиском сохранённого собственного токена до нового
POST. Прерванную явную замену продолжайте через `ensure`, сохраняя checkpoint.
Если MAS недоступен, сервер и ключи сохраняются; повторите `ensure`, а не init.
Состояние подтверждается MAS Admin API; временная недоступность не выдаётся за
«действителен». [Справочник MAS API](https://element-hq.github.io/matrix-authentication-service/topics/admin-api.html).

## Настройки сайта

Необязательный `settings/site.env` использует тот же загрузчик и схему.
Его отсутствие означает локальную главную страницу. Поля `HOMEPAGE_MODE`,
`HOMEPAGE_URL`, `SITE_NAME`, `SITE_DESCRIPTION`, `SITE_SUPPORT_URL` меняются
через раздел SSH-меню **Главная страница** или `sudo misbot homepage apply`.
[Поля, значения по умолчанию, проверка и восстановление](homepage.md) описаны отдельно.
Сгенерированные `public/site/` и Caddyfile вручную не редактируют.
