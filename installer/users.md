# Пользователи и сеансы MAS

Это руководство для администратора: выдать код приглашения, добавить личный административный
аккаунт, сменить пароль или завершить сеансы пользователя. Для подключения участника начните с
[первых шагов](README.md#6-запуск-и-проверка).

Команды выполняются по SSH на VPS с работающей установкой. В примерах каталог `/opt/matrix-stack` и
вымышленное локальное имя `example-user`; замените их своими. В командах MAS нужно **локальное
имя**, без `@` и домена, а в `admin access` — полный Matrix-адрес. Прямой Docker CLI не использует
блокировку Misbot: дождитесь окончания операций установщика перед его запуском.

## Регистрация и список

В SSH-меню откройте **Пользователи и приглашения → Пригласить пользователя**. После подтверждения
действующий код сохраняется, использованный, истёкший или отозванный заменяется. Передайте код
лично: новый участник вводит его в форме регистрации, затем открывает клиент и входит в созданный
аккаунт. Первый установочный код разрешает одну регистрацию и по умолчанию действует 7 дней.

CLI управляет этим сохранённым кодом отдельно от приглашений участников:

| Команда `sudo misbot users invitation …` | Результат |
| --- | --- |
| `ensure` | Создать первый код или закончить прерванную выдачу с тем же кодом; существующий код не заменяется |
| `status` | Проверить состояние без показа кода и без создания нового |
| `show` | Показать только подтверждённый действующий код в интерактивном терминале |
| `new` | Явно отозвать прежний код и создать замену |
| `revoke` | Отозвать сохранённый код |
| `list` | Показать все полученные от MAS приглашения без самих кодов |

После потери ответа при создании кода продолжайте через `ensure`, затем `status`
и `show`: команда сверяет сохранённый код с MAS перед повторным созданием.
Если прервался отзыв, повторите `revoke` по подсказке ошибки, а замену создавайте
только после подтверждённого отзыва. Повтор `new` означает ещё одну замену.
Состояния `unknown` и `unavailable` не подтверждают пригодность кода: проверьте
службы и повторите просмотр, сохраняя приватные данные выдачи. UI такие коды
не показывает и не заменяет.

`sudo misbot users invitation list` показывает приглашения, их авторов,
сроки и состояния: действует, использовано, истекло или отозвано. Коды не
выводятся. В SSH-меню: **Пользователи и приглашения → Показать приглашения**.
Если связь с приглашающим не сохранена, автор указан как «не указан».
Срок задаётся после установки в **Настройки сервера** и действует для будущих
приглашений. В UI показываются последние 1000 записей с явным указанием
ограничения; CLI возвращает весь полученный список.

Успех регистрации — новый пользователь может войти и отправить сообщение. Существующему аккаунту
приглашение не меняет пароль или права. Свои приглашения участник получает у `@referral-bot:<домен>`
командой `пригласить`; команды `токены` и `отозвать` показывают и отзывают его коды. Список
пользователей доступен администратору в Element Admin по адресу `https://admin.<домен>`. При ошибке
входа выполните `sudo misbot check` и проверьте административные права аккаунта.

MAS обслуживает пароли и вход. Смена пароля через старый Synapse Admin API не
заменяет операцию MAS; [документация Synapse](https://element-hq.github.io/synapse/latest/admin_api/user_admin_api.html)
описывает ограничения при делегированной авторизации.

## Добавить личного администратора

Зарегистрируйте местный аккаунт с выбранным именем, затем выполните `sudo misbot admin access add
--mxid @personal:example.org`, заменив адрес своим. Аккаунт получает полные права MAS admin и личный
доступ к панели; первоначальный `@matrix-admin` сохраняется. Список: `sudo misbot admin access
list`. Отзыв добавленных прав: `sudo misbot admin access remove --mxid @personal:example.org`. При
прерывании: `sudo misbot admin access recover`. Проверки и ограничения описаны в [панели администратора](admin-panel.md#личный-аккаунт-администратора).

## Временно запретить новый вход

Прямые команды Docker в этом и следующих двух разделах относятся к MAS
из обычного Compose-стека Misbot. Для внешнего MAS или индивидуально подключённого
стека используйте его собственные адреса, конфигурацию и средства администрирования;
локального контейнера `mas` там может не быть.

```bash
sudo docker compose --project-directory /opt/matrix-stack -f /opt/matrix-stack/compose.yaml exec -T mas /usr/local/bin/mas-cli manage --config /config/mas.yaml lock-user example-user
```

Успех — код завершения 0; новый вход по паролю запрещён. Проверяйте его отдельной попыткой входа.
Для прекращения существующих сеансов выполните также отзыв ниже: одна блокировка не является
подтверждением отзыва всех токенов. Повтор блокировки допустим. Не используйте `--deactivate` для
временной блокировки: это другая операция с отдельным порядком восстановления.

## Разрешить вход снова

```bash
sudo docker compose --project-directory /opt/matrix-stack -f /opt/matrix-stack/compose.yaml exec -T mas /usr/local/bin/mas-cli manage --config /config/mas.yaml unlock-user example-user
```

Успех — код завершения 0 и новый вход по прежнему паролю. Если страница говорит о слишком частых
попытках, дождитесь указанного ею времени и повторите один раз. Не меняйте пароль из-за ограничения
частоты попыток.

## Отозвать существующие сеансы

```bash
sudo docker compose --project-directory /opt/matrix-stack -f /opt/matrix-stack/compose.yaml exec -T mas /usr/local/bin/mas-cli manage --config /config/mas.yaml kill-sessions example-user
```

Успех — код завершения 0; прежний refresh token больше не обновляет сеанс, новый вход по прежнему
паролю возможен. Клиент может обнаружить отзыв при следующем обновлении токена; немедленное
прекращение действия каждого кэшированного access token не гарантируется. Пользователю потребуется
повторный вход. Для доступа к зашифрованной истории могут понадобиться его ключ восстановления или
другое доверенное устройство; серверная копия их не заменяет.

## Ошибка и возвращение к операции

Несуществующее имя приводит к ненулевому коду завершения; аккаунт не создаётся. Проверьте имя в
административном списке, исправьте только имя и повторите. Если контейнер MAS недоступен, проверьте
`sudo misbot status`, затем `sudo misbot check` и приватные журналы по
[administration.md](administration.md). Не выполняйте `init` и не удаляйте ключи для исправления
входа. Эти три операции не требуют остановки сервера или изменения DNS. После потери SSH сначала
проверьте фактический вход и при необходимости повторите нужную команду.

Смена первоначального пароля — отдельная операция [credentials.md](credentials.md).
Для обычного пользователя доступна операция ниже. Не передавайте реальный
пароль аргументом `mas-cli set-password`: он виден в списке процессов и истории.

## Сменить пароль обычного пользователя

В SSH-сессии на установленном VPS создайте закрытый файл и откройте редактор:

```bash
sudo install -m 600 /dev/null /root/matrix-user-password.json
sudo nano /root/matrix-user-password.json
```

Вымышленный пример структуры; замените оба значения своими:

```json
{"username":"example-user","password":"Replace-this-fictional-password_123!"}
```

Имя — существующее локальное имя без `@` и домена, строчные буквы/цифры и `._=-`. Пароль — 16–1024
символа без управляющих символов. Файл принадлежит root, права 600; символьные и жёсткие ссылки,
доступ группе и остальным запрещены. Команда не создаёт аккаунты, не меняет admin права и отказывает
для locked/deactivated или административного пользователя. Для `matrix-admin` используйте
[`credentials admin set`](credentials.md#пароль-первоначального-администратора).

```bash
sudo misbot users password set --input /root/matrix-user-password.json
sudo misbot check
```

Установщик сначала проверяет существующую активную обычную учётную запись, затем создаёт
согласованную резервную копию и проверяет восстановление всех включённых БД. Копирование кратко останавливает
пишущие службы и возвращает прежнее состояние; сама смена пароля выполняется при работающих
MAS/Synapse. Дождитесь проверки готовности служб; успех — `user_password_changed`, `passed=true`,
код 0. В новой браузерной сессии войдите с новым паролем; существующая сессия не подтверждает его
смену. Смена не отзывает все токены и не восстанавливает ключи зашифрованной истории.

Если имя не найдено, аккаунт заблокирован, файл/пароль некорректны или MAS
недоступен до проверки аккаунта, пароль не меняется. Исправьте причину, верните
MAS по инструкции выше, повторите команду с тем же приватным файлом.

После отправки запроса, таймаута или прерывания пароль мог уже измениться. Сохраняется закрытый
`secrets/user-password-pending.json` с новым паролем, доменом и подтверждённым внутренним MAS ID.
Другая операция смены пароля пользователя откажет до восстановления. Старый пароль не извлекается из
БД и автоматически не возвращается: восстановление повторяет установку выбранного **нового** пароля
для того же ID, без восстановления всей БД и потери последующих сообщений.

```bash
sudo misbot users password recover
sudo misbot check
```

Успех — `user_password_recovered`, `passed=true`, код 0; проверьте новый вход. Если проверка
готовности опять не прошла, checkpoint остаётся: восстановите службы и повторите recover. При
изменившемся ID или неактивном аккаунте recover откажет; сохраните checkpoint для приватной
административной проверки. Повтор recover после успеха сообщает, что pending нет; новая исходная
команда с тем же паролем допустима и снова создаёт проверяемую копию. После подтверждённого входа
удалите файл ввода; checkpoint удаляется только после успешного ответа API и проверки готовности
служб. Сохранённые резервные копии и версии Vault могут содержать его: держите их закрытыми.

Резервная копия сервера включает незавершённую операцию в `secrets`; на восстановленной машине она
применима к тому же домену/ID. Закончите восстановление пароля до финального переноса. Vault
получает снимок локальных секретов; при его недоступности сохраняются локальный кэш и отметка для
последующей команды `sudo misbot credentials vault sync`. Модель административного доступа описана в
[официальной инструкции MAS](https://element-hq.github.io/matrix-authentication-service/topics/admin-api.html). После
команды проверьте обычный вход пользователя и сохранение его данных.

## Границы подтверждения

Проверьте обычный вход, блокировку/разблокировку и завершение сеансов на своей установке. Блокировку
внешнего OAuth, деактивацию и создание аккаунта через CLI это руководство не описывает. Успешная
команда и `misbot check` не заменяют проверку входа в клиент и доступа к зашифрованной истории.
