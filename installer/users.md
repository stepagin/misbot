# Пользователи и сеансы MAS

Команды выполняет администратор по SSH на VPS с работающей установкой.
В примерах каталог `/opt/matrix-stack`, вымышленное локальное имя `example-user`.
Замените имя на нужное **локальное имя MAS**, без `@` и домена. Дождитесь окончания
операций установщика: прямой Docker CLI не использует его блокировку.

## Регистрация и список

Для обычного пользователя получите приглашение по [README §6](README.md#6-запуск-и-проверка),
откройте регистрацию в клиенте и введите код. Срок и число регистраций ограничены.
Успех — новый пользователь может войти и отправить сообщение. Существующему аккаунту
приглашение не меняет пароль или права. Список пользователей доступен администратору
в Element Admin; правильность адреса и прав проверяйте через `install.sh check`.

MAS обслуживает пароли и вход. Смена пароля через старый Synapse Admin API не
заменяет операцию MAS; [документация Synapse](https://element-hq.github.io/synapse/latest/admin_api/user_admin_api.html)
описывает ограничения при делегированной авторизации.

## Временно запретить новый вход

```bash
sudo docker compose --project-directory /opt/matrix-stack -f /opt/matrix-stack/compose.yaml exec -T mas /usr/local/bin/mas-cli manage --config /config/mas.yaml lock-user example-user
```

Успех — exit 0; новый вход по паролю запрещён. Проверяйте его отдельной попыткой
входа. Для прекращения существующих сеансов выполните также отзыв ниже:
одна блокировка не является подтверждением отзыва всех токенов.
Повтор блокировки безопасен и проверен. Не используйте `--deactivate` для временной
блокировки: деактивация и её обратный путь здесь не проверены.

## Разрешить вход снова

```bash
sudo docker compose --project-directory /opt/matrix-stack -f /opt/matrix-stack/compose.yaml exec -T mas /usr/local/bin/mas-cli manage --config /config/mas.yaml unlock-user example-user
```

Успех — exit 0 и новый вход по прежнему паролю. Повтор проверен. Если страница
говорит о слишком частых попытках, дождитесь указанного ею времени и повторите
один раз. В тестовой серии ограничение исчезло примерно через 19 секунд;
это наблюдение, а не гарантированный срок. Не меняйте пароль из-за rate limit.

## Отозвать существующие сеансы

```bash
sudo docker compose --project-directory /opt/matrix-stack -f /opt/matrix-stack/compose.yaml exec -T mas /usr/local/bin/mas-cli manage --config /config/mas.yaml kill-sessions example-user
```

Успех — exit 0; прежний refresh token больше не обновляет сеанс, новый вход
по прежнему паролю возможен. Повтор безопасен и проверен. Клиент может обнаружить
отзыв при следующем обновлении токена; немедленное прекращение действия каждого
кэшированного access token этим тестом не подтверждено. Пользователю потребуется
Повторный вход. Для доступа к зашифрованной истории могут понадобиться его ключ
восстановления или другое доверенное устройство; серверная копия их не заменяет.

## Ошибка и возвращение к операции

Несуществующее имя приводит к ненулевому exit; тест не создал аккаунт автоматически.
Проверьте имя в административном списке, исправьте только имя и повторите.
Если контейнер MAS недоступен, проверьте `install.sh status`, затем `check` и
приватные журналы по [administration.md](administration.md). Не выполняйте `init`
и не удаляйте ключи для исправления входа. Эти три операции не требуют остановки
сервера или изменения DNS. После потери SSH сначала проверьте фактический вход
и при необходимости повторите нужную команду.

Смена первоначального пароля — отдельная операция [credentials.md](credentials.md).
Для обычного пользователя доступна операция ниже. Не передавайте реальный
пароль аргументом `mas-cli set-password`: он виден в списке процессов и истории.

## Сменить пароль обычного пользователя

В SSH-сессии на установленном VPS создайте закрытый файл и откройте редактор:

```bash
sudo install -m 600 /dev/null /root/matrix-user-password.json
sudo nano /root/matrix-user-password.json
```

Вымышленный пример структуры; замените оба значения своими:

```json
{"username":"example-user","password":"Replace-this-fictional-password_123!"}
```

Имя — существующий локальный username без `@` и домена, строчные буквы/цифры
и `._=-`. Пароль —16–1024 символа без управляющих символов. Файл принадлежит
root, mode600; symlink/hardlink и доступ группе/остальным запрещены. Команда
не создаёт аккаунты, не меняет admin права и отказывает для locked/deactivated
или административного пользователя. Для matrix-admin используйте admin-password.

```bash
sudo bash /opt/matrix-stack/install.sh user-password /root/matrix-user-password.json
sudo bash /opt/matrix-stack/install.sh check
```

Установщик сначала проверяет существующую активную обычную учётную запись,
затем создаёт согласованную копию и проверяет восстановление обеих БД. Backup
кратко останавливает пишущие службы и возвращает прежнее состояние; сама смена
пароля выполняется при работающих MAS/Synapse. Ждите завершения backup/readiness;
успех — `user_password_changed`, passed=true, exit0. В новой браузерной сессии
войдите с новым паролем; существующая сессия не подтверждает его смену. Смена
не отзывает все токены и не восстанавливает ключи зашифрованной истории.

Если имя не найдено, аккаунт заблокирован, файл/пароль некорректны или MAS
недоступен до проверки аккаунта, пароль не меняется. Исправьте причину, верните
MAS по инструкции выше, повторите команду с тем же приватным файлом.

После применения API, timeout или прерывания пароль мог уже измениться.
Сохраняется закрытый `secrets/user-password-pending.json` с новым паролем,
доменом и подтверждённым внутренним MAS ID. Другая user-password операция
откажет до recovery. Старый пароль не извлекается из БД и автоматически не
возвращается: восстановление повторяет установку выбранного **нового** пароля
для того же ID, без восстановления всей БД и потери последующих сообщений.

```bash
sudo bash /opt/matrix-stack/install.sh user-password-recover
sudo bash /opt/matrix-stack/install.sh check
```

Успех — `user_password_recovered`, passed=true, exit0; проверьте новый вход.
Если readiness опять отказала, checkpoint остаётся: восстановите службы и
Повторите recover. При изменившемся ID или неактивном аккаунте recover откажет;
сохраните checkpoint для приватной административной проверки. Повтор recover
после успеха сообщает, что pending нет; новая исходная команда с тем же паролем
допустима и снова создаёт проверяемую копию. После подтверждённого входа удалите
файл ввода; checkpoint удаляется только после API/readiness успеха. Сохранённые
backup/Vault версии могут содержать его: держите их закрытыми.

Server backup включает pending в secrets; на восстановленной машине он
применим к тому же домену/ID. Закончите password recovery до финального переноса.
Vault получает обычный локальный secret snapshot; его недоступность оставляет
complete local cache и dirty marker с дальнейшей командой vault-sync.
Модель административного доступа описана в [официальной инструкции MAS](https://element-hq.github.io/matrix-authentication-service/topics/admin-api.html).
После команды проверьте обычный вход пользователя и сохранение его данных.

## Границы подтверждения

Проверьте обычный вход, lock/unlock и завершение сессий для своей установки. CLI-регистрация, деактивация, блокировка внешнего OAuth и приёмка реальными клиентами требуют отдельных проверок.
