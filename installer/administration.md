# Ежедневное управление сервером

Выполняйте команды по SSH на VPS. Ниже предполагается каталог `/opt/matrix-stack`; замените его в
командах, если выбрали иной при установке. Каталог содержит локальные данные и настройки. Внешние
PostgreSQL, S3 и MAS нужно учитывать отдельно по их руководствам. Домен и `server_name` сохраняют на
протяжении жизни установки, включая переезд.

## Краткая памятка

Для ежедневной работы откройте `sudo misbot ui` или выберите команду в таблице. Начните с `status`:
он показывает состояние установки, контейнеры и дальнейшие действия. Затем `check` проверит
доступность служб. Отрицательный результат во время резервного копирования или временной остановки
может быть ожидаемым.

Операции изменения одной установки используют общую блокировку. При занятой операции дождитесь её
окончания, проверьте `status` и повторите нужную команду. Не удаляйте lock-файл: прямые `docker
compose` и ручное редактирование файлов обходят защиту от одновременных изменений.

| Задача | Команда / инструмент | Успех и проверка | При ошибке |
|---|---|---|---|
| Состояние контейнеров | `sudo misbot status` | Контейнеры выбранной конфигурации running, health healthy либо отсутствует | starting может требовать ожидания; запустить check, найти службу в выводе |
| Проверка доступности служб | `sudo misbot check` | DNS, HTTPS/discovery, OAuth metadata, защищённые admin API, RTC/TURN TLS и службы успешны, exit 0 | Исправить указанную DNS/сетевую/служебную ошибку; повторить check |
| Запуск или продолжение | `sudo misbot start` | installation_running, затем успешный check | Следовать команде recovery из сообщения; сохранить существующие данные и credentials |
| Временная остановка | `sudo misbot stop` | `status` показывает остановленные службы; файлы и БД остаются | Проверить `status`; для возврата выполнить `sudo misbot start` |
| Освободить Compose-проект для восстановления в другой каталог | `sudo bash /opt/matrix-stack/install.sh down` | `installation_down`, контейнеры и принадлежащая установке сеть удалены; данные, секреты, копии и journals сохранены | При чужой сети/контейнере отказ до удаления; устранить конфликт с владельцем. Для возврата выполнить status, нужную команду восстановления и `sudo misbot start` из прежнего каталога |
| Свободное место | `sudo df -h /opt/matrix-stack` | Достаточно места для роста данных и копий; до первого запуска нужны 10 GiB, после образов минимум 3 GiB | Увеличить диск либо удалить согласованно выбранные старые копии после проверки внешней; повторить df |
| Оценить размер данных | `sudo du -sh /opt/matrix-stack/data /opt/matrix-stack/backups` | Размеры каталогов, без содержимого файлов | Большой S3 не освобождает локальный диск: локальные оригиналы сохраняются |
| Сделать и проверить копию | `sudo misbot backup create`, затем `sudo misbot backup verify` | `consistent_backup` и проверка всех включённых БД; см. [копии](backup.md) | Исправить диск/доступ к БД, повторить обе команды |
| Просмотреть пользователей | `https://admin.example.org` в браузере | MAS вход администратора, список пользователей в Element Admin | Проверить check, административные права аккаунта и выбранный homeserver |

Публичный check не подтверждает настоящий callback Google/Telegram, федерацию между серверами,
зашифрованную историю или звонок между двумя устройствами. Эти проверки выполняйте отдельно
реальными клиентами.

## После прерывания и при недоступном Docker

`status` выводит `installation_status`: незавершённые операции, признак заморозки, применённый
выпуск и `next_actions` с командами продолжения. Он ничего не запускает и не подтверждает
исправность сохранённого журнала восстановления.

После обрыва SSH, SIGINT или SIGKILL сначала дождитесь окончания активных процессов и выполните
`sudo misbot status`. Дочерний процесс может продолжать копирование или импорт после остановки
родителя и удерживать общую блокировку. Освобождение блокировки не означает успех операции. Следуйте
указанной команде восстановления; не выполняйте её одновременно с ещё работающим импортом. Пустой
`.matrix-installer-operation-….lock` рядом с каталогом установки может оставаться и после штатного
выхода — само наличие файла не означает занятую операцию.

Если Docker недоступен, `status` может отказать ещё при проверке принадлежности установки. Данные и
журналы при этом не удаляются. На VPS со штатным локальным Docker проверьте службу:

```bash
sudo systemctl status docker
sudo systemctl start docker
sudo misbot status
```

Запускайте Docker, если его остановка не была намеренным решением администратора. После его
восстановления сначала закончите незавершённую операцию по `status`, затем при необходимости
выполните `sudo misbot start` и `sudo misbot check`. Ошибка доступа к registry требует отдельной
проверки реквизитов. Remote Docker context не входит в поддерживаемую схему локальной установки.

Для замороженного источника переноса `check` ожидаемо сообщает об остановленных службах записи.
Снимать заморозку можно только после остановки цели и возврата DNS по [инструкции переноса](lifecycle.md).

## Журналы и диагностика

После временной остановки обработчик обновления TURN-сертификата не запускает остановленный или
отсутствующий LiveKit. Запись `turn_certificate_reload_deferred` означает отложенное применение при
следующем `sudo misbot start`. Проверьте `status`; для возврата выполните `sudo misbot start` и
`sudo misbot check`. Работающий LiveKit кратко перезапускается после изменения сертификата. Для
удаления установки и выключения машины следуйте [жизненному циклу](lifecycle.md).

Выберите службу из status. Например, посмотреть последние строки Synapse/MAS:

```bash
sudo docker compose --project-directory /opt/matrix-stack -f /opt/matrix-stack/compose.yaml logs --tail=100 synapse mas
sudo misbot config preflight
sudo ss -lntup
```

Для непрерывного просмотра выполните ту же `docker compose` команду с `logs --follow --tail=20
synapse mas`. Ctrl+C заканчивает просмотр; службы продолжают работать. Код завершения 130 при таком
прерывании ожидаем. Повторите `status` и `check`, если нужно подтвердить состояние. Не публикуйте
вывод журналов. Обрыв SSH также требует повторной проверки состояния, а не удаления данных или
lock-файла.

Журналы просматриваются приватно: в них могут быть персональные данные и параметры OAuth. Вывод `ss`
показывает слушатели и занятые порты. Preflight проверяет систему, DNS, портовые конфликты, subnet и
применимый SOCKS5. Проверяйте семь A-записей и AAAA, даже если главный сайт уже открывается. После
DNS-исправления возможен старый ответ из кэша; повторите preflight после обновления TTL/кэша.

После неудачной первой попытки внешний postgres-client может оставить сеть. Её принадлежность своему
каталогу отмечается в Docker labels и проверяется вместе с subnet и bridge. Повтор запуска
использует собственную сеть. Чужую сеть или VPN-маршрут preflight отклоняет; изменение
установленного subnet требует отдельной операции, не простого редактирования env.

При недостатке RAM проверяйте `free -h`, `swapon --show` и приватно `sudo journalctl -k --since '30
minutes ago'`. Если служба завершена OOM, увеличьте память/swap или уменьшите нагрузку, затем
повторите `sudo misbot start` и `sudo misbot check`. Продолжительное starting заканчивается
сообщением с точной командой журнала и повторного запуска.

## Пользователи и приглашения

Первоначальный `matrix-admin` имеет административные права; личные местные аккаунты добавляются
через `sudo misbot admin access add --mxid @personal:example.org`. Это выдаёт полные права MAS admin
и доступ к [панели администратора](admin-panel.md). Обычный referral-бот использует отдельную
ограниченную управляющую службу. Его команды `пригласить`, `токены`, `отозвать`, `помощь` описаны в
[README §6](README.md#6-запуск-и-проверка). Административный бот — отдельный обычный аккаунт;
серверные права оператора проверяет backend. [Федерация](federation.md) описывает allowlist, заявки,
recovery и комнаты. Приглашение разрешает регистрацию нового аккаунта, а не меняет права
существующего. Проверяйте количество разрешённых регистраций, срок и факт отзыва кода.

Для пользователей список, комнаты и медиа доступны в Element Admin. Пароли обслуживает MAS: поле
смены пароля в старом Synapse Admin API не является операцией смены пароля MAS. Смена
первоначального пароля реализована отдельно в [credentials.md](credentials.md). Обычному
пользователю пароль задаётся через `sudo misbot users password set --input PRIVATE_JSON`; после
прерывания — `sudo misbot users password recover`. Подготовка закрытого файла и границы
подтверждённых проверок находятся в [users.md](users.md). Команды MAS для временной блокировки,
разблокировки и отзыва сеансов, проверка результата и ограничения описаны в [users.md](users.md).

## Настройки и обновления

```bash
sudo misbot backup create
sudo misbot backup verify
sudo nano /opt/matrix-stack/settings/server.env
sudo misbot start
sudo misbot check
```

Для обычных изменений предпочтительно меню **Настройки сервера**: оно сохраняет черновик и
запрашивает подтверждение. При ручной правке `settings/*.env` следуйте [руководству конфигурации](configuration.md); не выполняйте env-файл как shell-команду. Запуск может пересоздать
службы, поэтому планируйте перерыв. `config generate` записывает конфигурации без перезапуска;
следующий запуск применит их. При неверном вводе исправьте поле по сообщению и повторите.
Сохранённые реквизиты и ключи не заменяйте для устранения сетевой ошибки.

Для обычной установки `sudo misbot update check` проверяет опубликованные выпуски, `sudo misbot
update latest` скачивает последний стабильный релиз и проверяет допустимость перехода перед
применением; несовместимое обновление отклоняется. Альтернатива — из нового распакованного
доверенного комплекта: `sudo python3 misbot.py update --directory /opt/matrix-stack`, затем `sudo
misbot check`. Для [existing-compose](existing-compose.md) используйте проверенный source plan через
SSH. Порядок, версии и ограничения отката — в [README §10](README.md#10-обновление). Реализован
ограниченный переход Synapse 1.161.0→1.162.0 с прежними остальными закреплёнными образами и
проверкой фактической схемы перед откатом. Произвольная смена digest и major PostgreSQL остаются
отдельными неподдерживаемыми путями. Откат исходников не восстанавливает прежнюю схему данных.

## Сложные операции и остановка записи

| Операция | Подробная инструкция | Когда останавливается сервер |
|---|---|---|
| Локальная/внешняя копия и восстановление | [backup.md](backup.md) | Writers остановлены для снимка; отправка/скачивание внешнего архива выполняются после их возвращения |
| Подключить S3 позднее, перенести медиа | [storage.md](storage.md) | После проверенной копии Synapse остановлен на перенос |
| Внешняя PostgreSQL | [storage.md](storage.md), [backup.md](backup.md#внешняя-postgresql-восстановление-в-локальную) | Первоначальное подключение до запуска; поздний local→external останавливает writers для финального снимка; external→local через полное staged восстановление |
| Смена пароля matrix-admin | [credentials.md](credentials.md) | Короткая остановка writers для pre-change backup; затем MAS API и проверка |
| Переезд с сохранением домена | [README §8](README.md#8-резервная-копия-и-восстановление), [lifecycle.md](lifecycle.md) | Финальный снимок замораживает источник; цель остаётся staged до остановки источника и DNS |
| Отключение и удаление установки | [lifecycle.md](lifecycle.md) | После проверенной внешней копии и приёмки новой машины; stop сохраняет установку, удаление данных и выключение машины — отдельные действия |

Приёмку выполняйте для выбранной конфигурации: проверьте вход, историю,
медиа, федерацию, звонки и пригодность копии. Автоматический retention не
реализован; очистка серверных данных требует отдельного решения и проверенного восстановления.
