# Ежедневное управление сервером

Выполняйте команды по SSH на VPS. Ниже предполагается каталог
`/opt/matrix-stack`; замените его в командах, если выбрали иной при установке.
Все рабочие данные сохраняются в этом каталоге. Домен и `server_name` сохраняют
на протяжении жизни установки, включая переезд.

## Краткая памятка

В установщике  операции изменения одной установки используют общую
блокировку: запуск/остановка, генерация, обновление, копии, восстановление,
перенос, смена пароля и подключение медиа. Если другая операция ещё идёт,
команда объяснит отказ и предложит `status`, ожидание и повтор той же команды.
`status` и `check` доступны во время работы; временно остановленные службы
могут дать отрицательный результат `check`. Не удаляйте lock-файл работающего
процесса: это позволит другой команде изменить данные одновременно.

Внутренние дочерние команды обновления проходят под той же блокировкой.
дочерний процесс сохраняет открытый descriptor блокировки:
после SIGKILL родителя другая операция остаётся заблокированной, пока дочерняя
команда не завершилась. После выхода последнего держателя ОС освобождает lock;
это не означает завершения операции. Проверьте `status` и используйте
соответствующую команду восстановления для pending-состояния. Файл
`.matrix-installer-operation-….lock` расположен рядом с каталогом установки
и остаётся пустым после штатного выхода. Его удаляют вместе с установкой,
когда все её операции закончились. Прямые команды `docker compose` и ручное
редактирование файлов эту блокировку не используют: дождитесь окончания
операции установщика перед такими действиями.

`status` сначала выводит `installation_status`: флаги freeze и
известных pending операций, применённый выпуск и `next_actions` с точными
командами. Затем показывает все созданные контейнеры, включая exited.
Тело recovery journals и файлы credentials для этого вывода не читаются.
После SIGKILL или обрыва SSH дождитесь завершения активной операции, затем
используйте указанную recovery/retry команду. Сам `status` ничего не запускает
и не подтверждает пригодность повреждённого journal. После успешной проверки
принадлежности установки локальные pending flags печатаются до запроса
Docker ps. Если сам Docker недоступен, проверка принадлежности может отказать
раньше этого вывода. Известный отказ соединения с Docker daemon
объясняет, что данные/журналы не удалены, и предлагает точные команды.
На VPS со штатным локальным Docker выполните:

```bash
sudo systemctl status docker
sudo systemctl start docker
sudo misbot status
```

После восстановления Docker сначала закончите pending операцию по `status`,
затем при необходимости выполните `up` и `check`. Эти команды не требуют удаления
данных или повторного `init`. Если Docker намеренно остановлен администратором,
согласуйте момент его запуска; ошибка registry credentials не является отказом
daemon и требует своей диагностики. Нестандартный remote Docker context не входит
в поддерживаемую схему локальной установки. Изолированный отказ запроса ps
не подтверждает полноценный отказ Docker на VPS.
У frozen source обычный check ожидаемо сообщает об остановленных writers;
отмена разрешена только после остановки target и возврата DNS.

та же передача lock descriptor охватывает прямые дочерние команды
pg_dump, pg_restore и генерацию RSA, которые раньше обходили общий run helper.
После SIGKILL ожидайте завершения дочерних процессов и проверьте journals;
восстановление не выполняйте одновременно с ещё работающим импортом.

| Задача | Команда / инструмент | Успех и проверка | При ошибке |
|---|---|---|---|
| Состояние контейнеров | `sudo misbot status` | Контейнеры выбранной конфигурации running, health healthy либо отсутствует | starting может требовать ожидания; запустить check, найти службу в выводе |
| Проверка публичной работы | `sudo misbot check` | DNS, HTTPS/discovery, OAuth metadata, защищённые admin API, RTC/TURN TLS и службы успешны, exit 0 | Исправить указанную DNS/сетевую/служебную ошибку; повторить check |
| Запуск или продолжение | `sudo misbot start` | installation_running, затем успешный check | Следовать команде recovery из сообщения; сохранить существующие данные и credentials |
| Временная остановка | `sudo misbot stop` | status показывает остановленные службы; файлы и БД остаются | Проверить status; после устранения причины выполнить up |
| Освободить Compose-проект для восстановления в другой каталог | `sudo bash /opt/matrix-stack/install.sh down` | `installation_down`, контейнеры и принадлежащая установке сеть удалены; данные, секреты, копии и journals сохранены | При чужой сети/контейнере отказ до удаления; устранить конфликт с владельцем. Для возврата выполнить status, нужную recovery-команду и up из прежнего каталога |
| Свободное место | `sudo df -h /opt/matrix-stack` | Достаточно места для роста данных и копий; до первого запуска нужны 10 GiB, после образов минимум 3 GiB | Увеличить диск либо удалить согласованно выбранные старые копии после проверки внешней; повторить df |
| Оценить размер данных | `sudo du -sh /opt/matrix-stack/data /opt/matrix-stack/backups` | Размеры каталогов, без содержимого файлов | Большой S3 не освобождает локальный диск: локальные оригиналы сохраняются |
| Сделать и проверить копию | `sudo misbot backup create`, затем `restore-check` | consistent_backup и две temporary_database_restore; см. backup.md | Исправить диск/доступ к БД, повторить обе команды |
| Просмотреть пользователей | `https://admin.example.org` в браузере | MAS вход администратора, список пользователей в Element Admin | Проверить check, административные права аккаунта и выбранный homeserver |

Публичный check не подтверждает настоящий callback Google/Telegram, федерацию
между серверами, зашифрованную историю или звонок между двумя устройствами.
Эти проверки выполняются отдельно реальными клиентами и записываются в журнал.

## Журналы и диагностика

После временной остановки handler обновления TURN-сертификата не запускает
остановленный или отсутствующий LiveKit. Запись `turn_certificate_reload_deferred`
означает отложенное применение при следующем сознательном `install.sh up`.
Проверьте `status`; для возврата выполните `up` и `check`. Running LiveKit по-прежнему
кратко перезапускается после изменения сертификата. Для удаления установки и
выключения машины следуйте [жизненному циклу](lifecycle.md).

Выберите службу из status. Например, посмотреть последние строки Synapse/MAS:

```bash
sudo docker compose --project-directory /opt/matrix-stack -f /opt/matrix-stack/compose.yaml logs --tail=100 synapse mas
sudo misbot config preflight
sudo ss -lntup
```

Для непрерывного просмотра выполните ту же `docker compose` команду с
`logs --follow --tail=20 synapse mas`. Ctrl+C заканчивает просмотр; службы
продолжают работать. Код выхода130 при таком прерывании ожидаем. Повторите
`status` и `check`, если нужно подтвердить состояние. Не публикуйте вывод
журналов. Обрыв SSH также требует повторной проверки состояния, а не удаления
данных или lock-файла.

Журналы просматриваются приватно: в них могут быть персональные данные и параметры
OAuth. Вывод ss показывает слушатели и занятые порты. Preflight проверяет систему,
DNS, портовые конфликты, subnet и применимый SOCKS5. Проверяйте семь A-записей
и AAAA, даже если главный сайт уже открывается. После DNS-исправления возможен
старый ответ из кэша; повторите preflight после обновления TTL/кэша.

После неудачной первой попытки внешний postgres-client может оставить сеть.
её принадлежность своему каталогу отмечается в Docker labels и проверяется
вместе с subnet и bridge. Повтор up использует собственную сеть. Чужую сеть или
VPN-маршрут preflight отклоняет; изменение установленного subnet требует отдельной
операции, не простого редактирования env.

При недостатке RAM проверяйте `free -h`, `swapon --show` и приватно
`sudo journalctl -k --since '30 minutes ago'`. Если служба завершена OOM, увеличьте
память/swap или уменьшите нагрузку, затем повторите up и check. Продолжительное
starting заканчивается сообщением с точной командой журнала и повторного запуска.

## Пользователи и приглашения

Первоначальный `matrix-admin` имеет административные права. Обычный referral-бот
использует отдельную ограниченную управляющую службу. Его команды `пригласить`,
`токены`, `отозвать`, `помощь` описаны в [README §6](README.md#6-запуск-и-проверка).
Административный бот — отдельный обычный аккаунт; серверные права оператора проверяет
backend. [Федерация](federation.md) описывает allowlist, заявки, recovery и комнаты.
Приглашение разрешает регистрацию нового аккаунта, а не меняет права существующего.
Проверяйте количество разрешённых регистраций, срок и факт отзыва кода.

Для пользователей список, комнаты и медиа доступны в Element Admin. Пароли
обслуживает MAS: поле смены пароля в старом Synapse Admin API не является
операцией смены пароля MAS. Смена первоначального пароля реализована отдельно
в [credentials.md](credentials.md). Обычному пользователю пароль задаётся
через `user-password PRIVATE_JSON`; после прерывания — `user-password-recover`.
Подготовка закрытого файла и границы подтверждённых проверок находятся в
[users.md](users.md). Команды MAS для временной
блокировки, разблокировки и отзыва сеансов, проверка результата и границы
изолированного опыта описаны в [users.md](users.md).

## Настройки и обновления

```bash
sudo misbot backup create
sudo misbot backup verify
sudo nano /opt/matrix-stack/settings/server.env
sudo misbot start
sudo misbot check
```

Редактируйте settings/*.env как файл, не выполняйте его shell-командой. Up может
пересоздать службы; планируйте перерыв. Generate записывает конфигурации на диск
без перезапуска, но следующий перезапуск применит их. При неверном вводе исправьте
поле по сообщению и повторите. Сохранённые credentials и ключи не заменяйте для
устранения сетевой ошибки.

Для обычной установки `sudo misbot update check` проверяет опубликованные
выпуски, `sudo misbot update latest` скачивает и применяет последний совместимый
релиз. Альтернатива — из нового распакованного доверенного комплекта:
`sudo python3 misbot.py update --directory /opt/matrix-stack`, затем
`sudo misbot check`. Для [existing-compose](existing-compose.md) используйте
проверенный source plan через SSH.
Порядок, версии и ограничения отката — в [README §10](README.md#10-обновление).
Реализован ограниченный переход Synapse 1.161.0→1.162.0 с прежними
остальными закреплёнными образами и проверкой фактической схемы перед откатом.
Произвольная смена digest и major PostgreSQL остаются отдельными неподдерживаемыми путями. Source rollback
не восстанавливает прежнюю схему данных.

| Операция | Подробная инструкция | Когда останавливается сервер |
|---|---|---|
| Локальная/внешняя копия и восстановление | [backup.md](backup.md) | Writers остановлены для снимка; отправка/скачивание внешнего архива выполняются после их возвращения |
| Подключить S3 позднее, перенести медиа | [storage.md](storage.md) | После проверенной копии Synapse остановлен на перенос |
| Внешняя PostgreSQL | [storage.md](storage.md), [backup.md](backup.md#внешняя-postgresql-восстановление-в-локальную) | Первоначальное подключение до запуска; поздний local→external останавливает writers для финального снимка; external→local через полное staged восстановление |
| Смена пароля matrix-admin | [credentials.md](credentials.md) | Короткая остановка writers для pre-change backup; затем MAS API и проверка |
| Переезд с сохранением домена | [README §8](README.md#8-резервная-копия-и-восстановление), [lifecycle.md](lifecycle.md) | Финальный снимок замораживает источник; цель остаётся staged до остановки источника и DNS |
| Отключение и удаление установки | [lifecycle.md](lifecycle.md) | После проверенной внешней копии и приёмки новой машины; stop сохраняет установку, удаление данных и выключение машины — отдельные действия |

Приёмку выполняйте для выбранной конфигурации: проверьте вход, историю,
медиа, федерацию, звонки и пригодность копии. Автоматический retention не
реализован; очистка серверных данных требует отдельного решения и проверенного восстановления.
