# Архитектура и варианты хранения

Этот справочник объясняет связи компонентов управляемой установки Misbot 1.2.0
и границы её данных. Для подключения внешнего ресурса используйте
[хранилища](storage.md), для действий после сбоя — [резервные копии](backup.md).
Подключённый [existing-compose](existing-compose.md) сохраняет свою архитектуру
и управляется по зарегистрированной инвентаризации.

## Компоненты и связи

| Компонент | Роль и зависимости |
| --- | --- |
| HAProxy (`tls-router`) и Caddy | Внешние HTTPS-маршруты, discovery, сайт, Matrix/MAS, веб-клиент и API. HAProxy распределяет TLS-трафик между Caddy и TURN LiveKit |
| Synapse | Комнаты, события, федерация и медиа; постоянные данные в PostgreSQL и `data/synapse` |
| MAS | Аккаунты и OAuth-сессии; при локальном режиме использует отдельную БД в PostgreSQL, при внешнем обслуживается независимо |
| PostgreSQL | Локальная служба для БД Synapse и локального MAS; при внешнем режиме её заменяют внешний кластер и контейнер `postgres-client` для операций |
| Element Web и Element Admin | Отдельные веб-приложения (`web`, `admin`); Element Admin не является Matrix-панелью `@admin-panel` |
| LiveKit и JWT | Звонки MatrixRTC, TURN и выдача разрешений; JWT обращается к Synapse, LiveKit использует TLS-сертификаты Caddy |
| `referral-bot` и `referral-control` | Зашифрованный чат приглашений и его управляющая служба; бот обращается к controller через Unix socket, controller работает с MAS/Synapse |
| `federation-bot` | Административная Matrix-панель и серверный помощник; разные аккаунты и криптосостояния, один контейнер |
| Host-служба [федерации/API](federation.md) | Общий backend операций, Unix RPC и узкий межсерверный HTTP API; вызывается панелью и Caddy через локальные сокеты |

Исходники и версии образов задают состав запуска; состояние установки, БД,
настройки и криптобазы находятся в постоянных каталогах. Образ контейнера
не является резервной копией этих данных. Не все службы имеют собственный
Docker healthcheck: готовность также проверяет установщик.

Telegram OAuth — способ входа через MAS. Необязательный управляющий
Telegram-бот подключается отдельно и не требуется для входа участников,
реферального бота или Matrix-панели.

## Основная конфигурация

| Область | Поведение и ограничения |
|---|---|
| Локальная PostgreSQL | Две БД и роли Synapse/MAS; приватные credentials; согласованные логические дампы |
| Локальные медиа | Постоянный media_store сохраняется вместе с БД и ключами |
| S3-медиа | Приватный HTTPS bucket/prefix, копирование существующих файлов через media-s3; локальные файлы сохраняются |
| Внешние копии | Отдельные credentials и prefix, authenticated encryption, проверка GET/decrypt/manifest и включённых дампов |
| Восстановление | Пустое staged назначение, сохранённый server_name и ключи; активация после остановки источника и переключения DNS |

По умолчанию MAS локальный, поэтому в копию входят две БД. При подключённом
внешнем MAS Misbot сохраняет только Synapse и локальные файлы; состояние
внешней авторизации сохраняют и восстанавливают отдельно.
[Границы копии и активации](backup.md#копии-при-внешнем-mas).

Архив пользователя содержит runtime и инструкции. Тесты, build tools, серверные
credentials и отчёты агента для установленного продукта не требуются.

## Сохранённые дополнительные возможности

Внешняя PostgreSQL и Vault KV v2/AppRole подключаются явно. Внешняя БД требует
выделенного PostgreSQL 18, TLS verify-full, доверенного CA и отсутствия чужих
одноимённых объектов. Поздний перенос выполняется через database-external с
checkpoint, остановкой writers и recovery. Редактирование hostname не переносит
данные. External→external не поддерживается; external→local выполняется через
`backup restore-local` в пустую staged установку. Автоматический перенос БД
при внешнем MAS не поддержан; восстановление Synapse в локальную БД описано
в [резервных копиях](backup.md#копии-при-внешнем-mas).

Vault сохраняет static snapshots секретных файлов, сверяет CAS/readback и
использует приватный локальный cache при outage. Dynamic database leases не
реализованы. Внешние Vault/OAuth/S3-сервисы имеют собственные данные и условия
восстановления: архив стека не заменяет их резервное копирование.

## Границы и проверка

`cli_commands.py` задаёт команды, аргументы, маршруты и поддержку существующего
Compose-стека. CLI выбирает доверенный runtime и передаёт ему отдельные аргументы,
без выполнения пользовательского ввода как shell-кода. CLI, UI и боты используют
общие модули операций; блокировки и recovery остаются в backend.

`backup_writers.py` управляет остановкой писателей и восстановлением
через приватный `backup-writers.json`. Каталог, чтение состояния, Compose,
ожидание готовности и вывод передаются явно. `lifecycle.py` сохраняет адаптер
для прежних вызывающих модулей; вложенные копии используют одну остановку.
Перенос источника и staged restore сохраняют запрет записи до явного
завершения соответствующей операции.
Внутренний результат recovery содержит код, этап, сообщение и следующее действие;
адаптер сохраняет прежние JSON-поля CLI и формат checkpoint `1`.

Команды и восстановление после ошибки описаны в [хранилищах](storage.md),
[Vault](vault.md), [копиях](backup.md) и [обновлении](README.md#10-обновление).
Проверяйте внешние TLS, права и отказы для своей конфигурации. Локальные тесты
не подтверждают OAuth, федерацию, звонки и клиентское E2EE recovery.

Обновление исходников не допускает произвольной замены component digest или
major PostgreSQL; допустимый переход проверяется по комплекту, а не только
номеру продукта. Перенос и recovery сохраняют domain/server_name, аккаунты,
БД, медиа, ключи, OAuth и состояние бота. Перед изменениями нужны пригодная копия,
проверка восстановления и свободное место. Автоматический retention не реализован.
