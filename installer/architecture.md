# Архитектура и варианты хранения

Misbot 1.0.0 использует Docker Compose с отдельными сервисами PostgreSQL,
Synapse, MAS, Element Web/Admin, Caddy, HAProxy, LiveKit, JWT и двумя сервисами
реферального бота, отдельным административным Matrix-ботом и узкой host-службой
[федерации/API](federation.md). Компоненты имеют собственные pins, healthchecks и постоянные
данные. Образ контейнера не является резервной копией этих данных.

## Основная конфигурация

| Область | Поведение и ограничения |
|---|---|
| Локальная PostgreSQL | Две БД и роли Synapse/MAS; приватные credentials; согласованные логические дампы |
| Локальные медиа | Постоянный media_store сохраняется вместе с БД и ключами |
| S3-медиа | Приватный HTTPS bucket/prefix, копирование существующих файлов через media-s3; локальные файлы сохраняются |
| Внешние копии | Отдельные credentials и prefix, authenticated encryption, проверка GET/decrypt/manifest и двух дампов |
| Восстановление | Пустое staged назначение, сохранённый server_name и ключи; активация после остановки источника и переключения DNS |

Архив пользователя содержит runtime и инструкции. Тесты, build tools, серверные
credentials и отчёты агента для установленного продукта не требуются.

## Сохранённые дополнительные возможности

Код внешней PostgreSQL и Vault KV v2/AppRole сохранён. Внешняя БД требует
выделенного PostgreSQL 18, TLS verify-full, доверенного CA и отсутствия чужих
одноимённых объектов. Поздний перенос выполняется через database-external с
checkpoint, остановкой writers и recovery. Редактирование hostname не переносит
данные. External→external не поддерживается; external→local выполняется через
restore-local в пустую staged установку.

Vault сохраняет static snapshots секретных файлов, сверяет CAS/readback и
использует приватный локальный cache при outage. Dynamic database leases не
реализованы. Внешние Vault/OAuth/S3-сервисы имеют собственные данные и условия
восстановления: архив стека не заменяет их резервное копирование.

## Границы и проверка

`cli_commands.py` задаёт команды, аргументы, маршруты и поддержку существующего
Compose-стека. CLI выбирает доверенный runtime и передаёт ему отдельные аргументы,
без выполнения пользовательского ввода как shell-кода. CLI, UI и боты используют
общие модули операций; блокировки и recovery остаются в backend.

Команды и восстановление после ошибки описаны в [хранилищах](storage.md),
[Vault](vault.md), [копиях](backup.md) и [обновлении](README.md#10-обновление).
Проверяйте внешние TLS, права и отказы для своей конфигурации. Локальные тесты
не подтверждают OAuth, федерацию, звонки и клиентское E2EE recovery.

Обновление исходников не допускает произвольной замены component digest или
major PostgreSQL. Перенос и recovery сохраняют domain/server_name, аккаунты,
БД, медиа, ключи, OAuth и состояние бота. Перед изменениями нужны пригодная копия,
Проверка восстановления и свободное место. Автоматический retention не реализован.
