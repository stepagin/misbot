# Misbot 1.2.0

- Проверка S3 автоматически подготавливает системный SDK на Ubuntu/Debian.
  Проверка запуска ждёт временно недоступные службы в пределах общего таймаута;
  управление доступом ожидает краткую занятость установки без повторения изменений.
- В SSH-меню доступны просмотр пароля, управление администраторами и скрытый ввод
  нового пароля пользователя. Выдача приглашения сразу показывает код; список
  содержит его статус, число регистраций и срок вместо служебного ID.
- Панель различает команды, текущие данные и постоянные памятки; продолжение
  изменения федерации предлагается только при наличии незавершённой операции.
  В терминале CLI федерации показывает обычный текст, а `--json` сохраняет
  технический формат. При перенаправлении вывода формат остаётся прежним.
- Мастер сначала проверяет DNS и показывает действия только для неверных записей;
  ожидание обновляет статусы с интервалом десять секунд между проходами.
- В итоге доступны номера полей и страницы; Enter сохраняет черновик и выходит.
  Неизвестный ввод сохраняет текущий экран, возврат из редактора открывает итог.
  Имя панели выбирается до создания, срок приглашений — после установки.
- Прерванный первоначальный запуск продолжается через start, затем check,
  с сохранением уже созданных баз, настроек и ключей.
- Индикатор операции расположен над выводом backend и движется при ожидании.
  Просмотр настроек панели и списков больше не теряется при перерисовке.
- Добавлены безопасный список приглашений без кодов и отдельный сброс черновика.
  Исправлено чтение стандартной политики федерации и просмотр операций во время работы.
- Длительный первоначальный запуск больше не блокируется перезапуском службы ботов;
  незавершённые задачи восстанавливаются после освобождения установочной блокировки.
- Приветствия ждут принятия приглашения; повтор сохраняет исходную доставку и ключи.
  Фоновые проверки панели объединяются, команды владельца получают приоритет.
- Для новых установок добавлен компактный комплект со скрытым служебным каталогом.
  Совместимый архив автоматического обновления сохраняет прежнюю структуру.

- Telegram и административный Matrix-бот используют разделы состояния, проверки,
  статистики и федерации. Обслуживание, копии и пользовательские приглашения
  сгруппированы отдельно; Matrix-панель ведёт к реферальному боту, Telegram
  добавляет ссылки Element X. Навигация Telegram обновляет одну карточку,
  сохраняя приглашения, уведомления и результаты операций.
- Управляющий Telegram-бот закреплён за одним сервером. Вход в тот же MAS account
  с нового Telegram-аккаунта заменяет прежний доступ и переносит его приглашения
  и результаты операций; старые подтверждения отменяются. Другой MAS account
  не получает историю прежней identity.
- Межсерверные приглашения проверяют поддержку Misbot API до отправки, действуют
  30 дней и ограничены одним новым приглашением в минуту. Добавлены отзыв,
  очистка отклонённых, продолжение незавершённого обмена и уведомления.
  Встречные заявки сходятся к одной записи; проверенная identity сохраняется.
  Старым runtime требуется обновление для новых 30-дневных заявок.
- Межсерверный API включён по умолчанию; его переключение сохраняется при перезагрузке
  без изменения Matrix allowlist. Длительные операции обслуживания работают
  через общую сохранённую очередь systemd и повторно проверяют права MAS.
- Имена групп CLI, включая `misbot update`, открывают справку с доступными
  действиями. Справка операций разделена на аргументы, примеры и условия;
  описания переносятся по ширине терминала, примеры сохраняют рабочие аргументы.
- CLI передаёт текст с ведущими дефисами буквально и не повторяет пользовательские
  значения в сообщении о правах. Слово `help` в значении поля остаётся данными.
- После ручного удаления установки сохранённый черновик проверки предлагает
  начать настройку с начала. Новый черновик сохраняет прежний приватно;
  оставшиеся данные сохраняются. Принадлежащую установке системную команду
  можно удалить без уже отсутствующего `installation.json`.
- Удаление установки и локальные копии работают без необязательного пакета
  шифрования `cryptography`. Ошибка удаления сообщает этап и безопасную причину;
  прежний план сохраняется для подтверждённого повторного запуска.
- Терминальный интерфейс на Rich: читаемые меню, обзор перед изменениями
  и показ этапов первоначальной настройки.
- В обычном SSH-терминале мастер работает на весь экран и возвращает прежний
  экран после выхода. `ui --plain` сохраняет последовательный вывод;
  итог установки закрывается после Enter.
- Главное меню, разделы и редактирование настроек заменяют предыдущую страницу.
  В небольшом окне меню разбивается на страницы с сохранением номеров действий
  и текущих значений. Загрузка и операции без запроса ввода показывают
  анимированный индикатор ожидания.
- Разделы управления организованы по задачам: работа сервера, приглашения,
  копии и расписание, хранилище, сайт, федерация и обновление.
- Одинаковая навигация для обычной и подключённой Compose-установки;
  меню показывает только поддерживаемые действия.
- Восстановление после прерывания вынесено в отдельный раздел.
  Отмена ввода возвращает в меню, изменения требуют подтверждения.
- Проверка доступности в UI объясняет отказы HTTPS/TURN и состояние служб;
  подробности доступны без повторного запуска. CLI сохраняет JSON с безопасным
  кодом причины. Успешная проверка DNS отделена от доступности HTTPS.
- Изменение сайта не создаёт checkpoint во время незавершённого запуска ботов.
  Старый checkpoint в такой установке можно откатить к сохранённым файлам
  без требования ещё не запущенного HTTPS; его проверяет завершение установки.
- Мастер проверяет ввод до сохранения: домены, пути, S3, расписание и аргументы
  операций. Международное имя подтверждается вместе с DNS-адресом, в том числе
  в старом черновике. После ошибки DNS `назад` возвращает к домену.
- Отказ от ранее выбранного OAuth или внешних копий учитывается при продолжении
  черновика. Существующие настройки работающего сервера сохраняются.
- Приглашения и пароль администратора показываются только по отдельному запросу.
- Исправлено разделение cross-signing панели администратора и серверного
  помощника: у каждого аккаунта свой файл ключей. Сбой помощника больше не
  возникает из-за чтения ключей панели и не блокирует первоначальный запуск
  HTTPS-служб. Существующие ключи, устройства и сессии сохраняются.
- Стандартный лендинг объясняет регистрацию по приглашению и вход в чат.
  В футере остаётся спокойная подпись «Сделано через Misbot»; индивидуальные
  шаблоны подключённых серверов сохраняются.
- Сохраняется простой вывод для узкого терминала, TERM=dumb и системы без Rich.
  Misbot и Rich используют MIT; лицензии описаны в [сведениях о компонентах](third-party-licenses.md).
- Новое штатное приветствие объясняет получение приглашения и обращение за помощью;
  название сервера и полные ссылки на бота и администратора берутся из настроек.
  Старый штатный текст заменяется при обновлении, включая вариант без точки после
  адреса бота; пользовательские приветствия и отметки доставки сохраняются.
- Ответ реферального бота на `пригласить` содержит код, срок в МСК и отдельные
  инструкции для телефона и компьютера с настройками своего сайта и веб-чата.
  Название кода остаётся личным; срок и лимит берутся из выданного приглашения.
  В `existing-compose` обновление исходников сохраняет принятый образ Matrix-бота;
  новый ответ требует отдельного обновления его runtime.
- Сообщения Telegram-бота и Matrix-ботов используют обращение на «вы» и
  одинаковые названия действий. Ответы о задачах различают принятие, выполнение,
  подтверждённый результат и прерывание; исходные коды состояний сохраняются.
  Команды, подтверждения, права и отметки доставки не меняются. Сохранённые
  пользовательские тексты и очередь сообщений сохраняются.

Версии компонентов и существующие форматы конфигурации сохраняются. SQLite бота
совместимо дополняется таблицами задач, уведомлений и владельцев Telegram-привязки.
Для старых одновременных входов одного MAS account сохраняется привязка с наиболее
поздним сроком входа; её история объединяется. Если до обновления пользователь
вышел и запись MAS-владельца уже удалена, оставшаяся история сохраняется отдельно
и не выдаётся новой identity без подтверждённого владельца. Обновление
сохраняет домен, ключи, настройки, историю и отметки доставки. Применение
и восстановление выполняются существующим backend с его блокировками.

## Изменения Misbot 1.1.1

- Команды управления комнатами административного бота удалены из CLI, SSH-меню
  и Matrix-панели; прежние операции backend и RPC отклоняются. Сохранённая
  конфигурация и внутренняя обработка приглашений сохраняются.
- Существующий Compose-стек может управлять зарегистрированными контейнерами Caddy
  и Telegram worker через `start`, `stop`, `status` и `check`.
- Проверка, применение и восстановление сайта используют выбранный Caddy runtime.
  Сохраняются индивидуальный шаблон сайта, TLS и Matrix identity; шаблон входит
  в зашифрованную резервную копию.
- Telegram worker получает только собственные настройки, SQLite и управляющий
  сокет. Привилегированная управляющая служба остаётся на хосте.
- Лендинг учитывает прежнее имя настройки обязательного приглашения в MAS 1.11;
  настройки регистрации принятого сервера изменяются администратором вручную.
- Резервная копия сохраняет актуальные настройки контейнерного worker и согласованный
  SQLite snapshot. Обновление изменённых исходников автоматически собирает и проверяет
  новый worker image, сохраняет прежний pin и восстанавливает его при сбое.

Обновление с 1.1.0 сохраняет прежний режим служб. Перенос существующих systemd-служб
в Compose выполняется отдельно после инвентаризации и проверки восстановления.
Новые поля инвентаризации необязательны; формат конфигурации и схема данных остаются
прежними. Домены, issuer, базы, сессии и ключи ботов не перегенерируются.

## Изменения Misbot 1.1.0

- Исходники доступны под лицензией MIT, автор — Stepan Ponamarev; текст лицензии входит
  в установочный архив.
- Административный бот `@admin-panel`, доступный только владельцу сервера;
  удобные команды, уведомления о версиях и регистрации, статистика.
- Обновление из готового GitHub Release с проверкой диска, подтверждением
  и сохранённым отчётом; автоматические транзакционные миграции данных панели.
- Приветственный бот `@server-guide`, редактируемое приветствие и рассылки
  с предварительным просмотром и подтверждением администратора.
- Многоэтапное удаление сервера, включая незавершённую установку и выбранные
  внешние данные; утилита сохраняется.
- Команды панели нечувствительны к регистру, тексты и идентификаторы сохраняются.

Обновление сохраняет домен, ключи, настройки, историю сообщений и отметки
доставки. Произвольная смена версий компонентов и major PostgreSQL не
поддерживается; допустимые переходы и recovery описаны в README комплекта.
Число и длительность зашифрованных звонков MatrixRTC в статистике недоступны.
