# Misbot 1.2.0 — Matrix на чистом сервере

Misbot устанавливает Matrix-сервер с браузерным чатом Element, звонками,
приглашениями и административной панелью. В Element X можно войти по основному
домену сервера. Доступны вход по паролю и необязательные Google/Telegram.
Для регистрации нужен код приглашения; его вводят в форме регистрации.

Руководство предназначено владельцу **нового чистого VPS**. Готовый сервер Misbot
переносят с сохранением домена, баз и ключей по разделу
[резервного копирования и восстановления](#8-резервная-копия-и-восстановление).
Другой Matrix Compose-стек сначала обследуют по
[отдельному контракту existing-compose](existing-compose.md); обычный мастер
не импортирует его аккаунты и историю.

Порядок новой установки: подготовьте VPS и DNS (разделы 1–2), запустите мастер
(быстрый запуск или раздел 3), проверьте сервер и клиенты (раздел 6), настройте
копии (раздел 8). Разделы 4–5 нужны только для выбранного Google/Telegram OAuth;
их можно пропустить при парольном входе.

Шифрование включено по умолчанию при создании комнат совместимыми клиентами.
Пароли администратора и служебные ключи создаются автоматически и сохраняются
при повторном запуске. Если создание администратора прервалось, повторите
`sudo misbot start`, сохранив данные и каталог `secrets`.

Основная конфигурация использует локальную базу данных, локальные медиа или S3
и защищённые внешние резервные копии. Подробные инструкции:
[команды Misbot](cli.md), [жизненный цикл установки](lifecycle.md),
[хранилища и перенос базы](storage.md), [смена паролей и ключей доступа](credentials.md),
[резервные копии](backup.md), [Vault](vault.md).

Размер одного вложения по умолчанию — **256 МиБ**. Его можно изменить в разделе
SSH-меню **Настройки сервера** или через `MAX_UPLOAD_SIZE_MIB` в
`settings/policy.env`; [порядок применения](configuration.md#размер-вложений).

Для новой установки доступен компактный комплект `misbot-setup-1.2.0.tar.gz`.
В его каталоге видны `misbot.py`, краткая инструкция и контрольные суммы;
служебные исходники и подробная документация находятся в `.misbot/`.
Запуск: `sudo python3 misbot.py ui`. Черновик хранится отдельно, приватно,
в `~/.local/state/misbot/wizard/`, чтобы распаковка комплекта его не перезаписывала.
Совместимый `matrix-installer.tar.gz` сохраняет прежнюю структуру и используется
существующими командами автоматического обновления. Оба комплекта обновляют
существующий сервер командой `sudo python3 misbot.py update` из каталога комплекта.

SSH-мастер позволяет настроить внешние копии, PostgreSQL, Vault и смену ключей
через формы без подготовки конфигурационных файлов вручную. Повторные операции
используют сохранённые параметры; заявки и аккаунты можно выбирать из списка.

## Быстрый запуск через SSH

```bash
curl -fL https://github.com/stepagin/misbot/releases/latest/download/install.sh -o ~/misbot-install.sh && sudo bash ~/misbot-install.sh
```

Файл `install.sh` появляется в GitHub Releases с релизом, содержащим загрузчик.
Нужны интерактивный SSH-терминал, `curl` и права sudo/root. При отсутствии `curl`:
`sudo apt-get update && sudo apt-get install -y curl ca-certificates`.
Загрузчик установит недостающие пакеты для мастера из репозиториев ОС, выберет
последний стабильный релиз, проверит архив и все внутренние контрольные суммы,
затем откроет UI. Домен и реквизиты задаются в мастере. Для выбора версии:
`sudo bash ~/misbot-install.sh --version 1.2.0` (также допускается `v1.2.0`).

Если системная команда Misbot уже установлена, загрузчик проверит её и откроет
UI без смены версии, включая запуск с `--version`. При повреждённой или посторонней
команде загрузка останавливается, существующие файлы не перезаписываются.
Временные загрузки удаляются, а проверенные исходники сохраняются в
`/var/lib/misbot-bootstrap/<версия>/matrix-installer` для повторного запуска и
восстановления. Черновики мастера остаются отдельно. После сетевого сбоя повторите
ту же команду; после выхода из мастера её также можно повторить.
Контрольные суммы обнаруживают повреждение файлов; доверие к источнику основано
на HTTPS и официальном репозитории `stepagin/misbot`.

## 1. Что подготовить

Нужен отдельный чистый VPS с публичным IPv4, Linux **amd64**, systemd, доступом
root/sudo и свободными портами из таблицы ниже. Поддерживаются Ubuntu 24.04/26.04
и Debian 12/13. Практический минимум для небольшой нагрузки — **2 vCPU,
2 ГиБ RAM, SSD 20 ГиБ**, минимум 10 ГиБ свободного диска до установки и
3 ГиБ после неё. Для роста и звонков планируйте 4 ГиБ RAM и SSD 40 ГиБ.
Медиа и обслуживание требуют дополнительного места. Проверка требует около
2 ГиБ физической RAM; swap не заменяет её. При RAM меньше 2 ГБ и отсутствии
достаточного swap установщик создаст файл swap размером 1 ГБ.

Для экспериментальной установки на VPS с меньшей RAM можно явно принять риск:
`sudo env MISBOT_ALLOW_LOW_MEMORY=1 misbot ui`,
`sudo env MISBOT_ALLOW_LOW_MEMORY=1 misbot config preflight` или
`sudo env MISBOT_ALLOW_LOW_MEMORY=1 misbot start`. Возможны нехватка памяти,
медленная работа и перезапуски служб; стабильность полного комплекта не гарантируется.
Разрешение действует только для текущего процесса и не сохраняется в настройках:
для повторного запуска задайте переменную снова. Проверки диска, DNS и портов
остаются обязательными.

Нужны права управления DNS выбранного домена и, для соответствующих способов входа, приложения OAuth в Google Cloud и BotFather. Исходящие HTTPS/DNS-запросы сервера должны быть разрешены. Если Telegram недоступен напрямую, нужен постоянный SOCKS5-прокси.

Выберите отдельный пустой каталог установки. Установщик устанавливает Docker и
настраивает необходимые системные службы. Если каталог, порты или Docker заняты
другой установкой, сначала устраните конфликт, сохранив её данные.

Далее `example.org` — **ваш** основной домен. Выберите его окончательно: он станет частью Matrix ID `@имя:example.org`. Изменение домена готовой установки или подмена его в старой базе не поддерживаются.

При инициализации вводите только имя домена, без `https://`, пути или порта.
При ошибке исправьте имя и повторите команду. Непустой каталог с неизвестными
данными сохраните и выберите другой каталог установки.
Для международного домена SSH-мастер показывает имя и его DNS-адрес и просит
подтверждение. Проверьте раскладку клавиатуры перед подтверждением.

## 2. DNS и сетевые порты

Для стандартной установки создайте семь записей **A** с одним публичным IPv4 VPS.
Таблица ниже использует вымышленный домен `example.org`; замените его своим.

По умолчанию MAS устанавливается на этот VPS и использует `mas.<DOMAIN>`.
В мастере можно вместо этого подключить уже настроенный внешний MAS. Его DNS
указывает на его собственный сервер; для этого VPS тогда нужны остальные шесть
A-записей. Подробнее — [конфигурация внешнего MAS](configuration.md#внешний-mas).
Для другого имени локального MAS
задайте `MAS_DOMAIN` в `settings/server.env` до первого запуска, например
`MAS_DOMAIN=auth.example.net`. Используйте его вместо `mas.example.org` в DNS
и настройках входа Google/Telegram. Адрес авторизации действующей установки
изменять нельзя. Подробности — в
[конфигурации](configuration.md#отдельный-домен-mas).

| Имя | Назначение |
|---|---|
| `example.org` | Адрес сервера для Element X и главная страница |
| `matrix.example.org` | Сообщения, вложения и федерация |
| `mas.example.org` | Вход и управление аккаунтом |
| `admin.example.org` | Веб-панель администратора |
| `web.example.org` | Браузерный чат Element |
| `rtc.example.org` | Звонки |
| `turn.example.org` | Звонки через ограниченные сети |

Для корня DNS-панели обычно используют имя `@`, для остальных — `matrix`, `mas`
и т. д. Удалите AAAA для управляемых имён этого VPS: комплект рассчитан на IPv4.
DNS внешнего MAS проверяйте по его отдельным требованиям.
Используйте режим DNS only, без HTTP/CDN-прокси. Если есть ограничивающие CAA,
разрешите `letsencrypt.org`. Дождитесь обновления DNS.

Проверка перед запуском сообщит об ошибке DNS или CAA и укажет проблемное имя.
Для ограничивающей политики поддержана запись `CAA 0 issue "letsencrypt.org"`.
Если отсутствует `dig`, выполните `sudo apt-get install dnsutils` и повторите
проверку. Сложные ограничения CAA требуют отдельной настройки.

Разрешите в сетевом экране провайдера и на сервере:

| Протокол и порт | Назначение |
|---|---|
| Ваш TCP-порт SSH | Администрирование; сохраните действующее правило |
| TCP 80 | HTTP и выпуск сертификатов Let's Encrypt |
| TCP 443 | HTTPS, федерация и защищённое соединение для звонков |
| TCP 7881 | Резервный транспорт WebRTC |
| UDP 7882 | Основной транспорт WebRTC |
| UDP 3478 | TURN/UDP |

Порты PostgreSQL 5432, Synapse 8008, MAS 8080 и LiveKit API 7880 наружу не публикуются. TCP 8448 не нужен: federation discovery указывает HTTPS 443. Диапазон UDP 50000–60000 не нужен при настроенном mux 7882. Комплект не включает UFW и не меняет правила вашего SSH. Учтите, что публикация портов Docker взаимодействует с iptables и может обходить обычные правила UFW; входящий доступ ограничивайте также экраном провайдера. Официальные источники: [Docker и firewall](https://docs.docker.com/engine/network/packet-filtering-firewalls/), [порты LiveKit](https://docs.livekit.io/transport/self-hosting/ports-firewall/).

## 3. Загрузка и создание файлов

Этот путь нужен, если загрузчик недоступен или вы устанавливаете выбранный
заранее полученный релиз. Скачайте `matrix-installer.tar.gz` и
`matrix-installer.tar.gz.sha256` из одного выбранного
[релиза](https://github.com/stepagin/misbot/releases). Для сборки из
исходников выполните `python3 installer/build.py` из корня репозитория;
файлы появятся в `dist/`. Локальная сборка добавляет к версии суффикс
`-build.N` и увеличивает счётчик в `dist/.local-build.json`, не меняя
`release.json` в исходниках. Сохраните этот файл счётчика при очистке архивов,
если хотите продолжить нумерацию. С `--release` или в CI собирается базовая
версия без суффикса; счётчик не используется. `--check` только проверяет
контрольные суммы исходников и не увеличивает номер.

Передайте архив и файл контрольной суммы на сервер через SCP. Сверьте
контрольную сумму с доверенным опубликованным значением, затем из каталога
с файлами выполните:

```bash
sha256sum -c matrix-installer.tar.gz.sha256
sudo install -d -m 700 /root/misbot-setup
sudo tar -xzf matrix-installer.tar.gz -C /root/misbot-setup
sudo sh -c 'cd /root/misbot-setup/matrix-installer && sha256sum -c SHA256SUMS'
sudo apt-get update
sudo apt-get install -y python3 python3-yaml python3-rich dnsutils iproute2
sudo python3 /root/misbot-setup/matrix-installer/misbot.py ui
```

Для компактного комплекта скачайте `misbot-setup-1.2.0.tar.gz` и его одноимённый
файл `.sha256` из того же релиза. Проверьте внешнюю контрольную сумму,
распакуйте в отдельный закрытый каталог и проверьте `SHA256SUMS` из
`matrix-installer/`. Запускайте находящийся там `misbot.py`; подробные файлы
этого комплекта находятся в `matrix-installer/.misbot/`.

Выполняйте команду в SSH-терминале Linux с Python 3.11 или новее. До установки используется `python3 misbot.py ui` из распакованного комплекта; после init системная команда `misbot` доступна из любого каталога. Мастер проверяет систему, DNS/CAA и порты, предлагает локальные медиа или проверку S3, необязательные способы входа и внешние копии. Enter сохраняет текущее значение или существующий секрет; запуск требует явного ввода `применить`. Команды ввода: `назад` (или `b`), `отмена`, `сохранить и выйти` (или `q`).
IPv4 определяется по единственной A-записи основного домена. Если её ещё нет,
мастер попросит адрес VPS и покажет, какие A-записи создать в панели DNS.
При возврате из проверки DNS итоговый экран остаётся доступен для исправлений.
Реквизиты S3 вводятся прямо в мастере; ключи скрыты. Возврат отменяет выбор S3.
Google и Telegram включаются и отключаются целиком, вместе с парой реквизитов.

В обычном SSH-терминале мастер и меню используют весь экран; переходы заменяют
предыдущую страницу. В небольшом окне `>` и `<` переключают страницы меню,
сохраняя номера действий. Загрузка и операции без запроса ввода сопровождаются
анимированным индикатором ожидания. Итог установки остаётся
до Enter; после выхода возвращается прежний экран терминала. Добавьте `--plain`
для последовательного вывода без оформления. Без Rich и при `TERM=dumb`
используется простой вывод; `NO_COLOR=1` отключает цвет и полноэкранный режим.

Меню управления разделено по задачам: состояние сервера, приглашения, копии,
хранилище, сайт, федерация и обновление. Перед изменениями показываются
параметры и последствия; Enter отменяет подтверждение. Для прерванной операции
сначала проверьте состояние, затем откройте соответствующий раздел восстановления.
Подробности и режимы оформления: [терминальный интерфейс](cli.md#управление-через-терминал).
Rich используется под MIT; [текст лицензии](third-party-licenses.md) входит в комплект.

Для другого каталога: `sudo python3 misbot.py --directory '/opt/My Matrix' ui`.
После «сохранить и выйти» мастер показывает команды продолжения, просмотра
и удаления приватного черновика. До инициализации повторите запуск `misbot.py ui`
из этого комплекта с тем же каталогом установки; после регистрации системной
команды используйте `sudo misbot ui`.
Если мастер просит TTY, подключитесь
с `ssh -t`. Пароли вводятся без отображения символов.

В конце мастер показывает `@matrix-admin:example.org` и адрес входа.
Кнопка **Показать пароль администратора** открывает пароль в этом терминале.
Раздел **Администраторы и доступ** позволяет выдать права уже зарегистрированному
личному аккаунту. Для новой регистрации выберите **Пользователи и приглашения →
Пригласить пользователя**: мастер подготовит и покажет код на одну регистрацию.
По умолчанию он действует 7 дней. Код вводят в форме регистрации, не в URL.
После подтверждения действие сохраняет действующий код; использованный,
истёкший или отозванный заменяет. Если выдача ещё не завершена, повторите
действие; переустановка не нужна. При работе через CLI `ensure` только создаёт
или продолжает выдачу сохранённого кода, а для замены нужен явный
`sudo misbot users invitation new`, затем `sudo misbot users invitation show`.

Для настройки без мастера используйте [создание через CLI](configuration.md#создание-установки-через-cli)
и [таблицу полей](configuration.md#поля). Основной `settings/server.env` содержит
домен, публичный IP, email и режимы хранения. Условные файлы нужны только для
выбранных ресурсов. `settings/policy.env` содержит параметры регистрации и
федерации; без файла используются значения по умолчанию. Существующий
`settings.env` поддерживается до явного `sudo misbot config migrate`.

Основной домен показывает локальный [лендинг](homepage.md). «Открыть чат» и «Зарегистрироваться» открывают штатный клиент/MAS; приглашение вводится в форме, не в URL. Настройки сайта — необязательный `settings/site.env`, раздел UI «главная страница» и `sudo misbot homepage help`. `sudo misbot homepage apply --mode element` выбирает Element; `--mode external --url https://community.example.net/` — временную внешнюю переадресацию, `--mode landing` возвращает страницу. Проверка маршрутов не заменяет настоящий браузерный вход.

После ручного редактирования: `sudo misbot config validate`, затем
`sudo misbot config apply` и `sudo misbot check`. При уже инициализированных БД
перед применением создаётся и проверяется резервная копия; до первого запуска
сохраняется снимок настроек. Изменяйте только пользовательские настройки;
для паролей и ключей доступа используйте [специальные команды](credentials.md).
Домен действующего сервера менять нельзя. Файлы env не выполняйте через `source`.

## 4. Google

Дальнейшие шаги относятся к необязательному входу через Google на локальном MAS
(`MAS_MODE=local`). Используйте его фактический домен вместо `mas.example.org`;
реквизиты внесите в мастер или `settings/auth.env`. При внешнем MAS провайдер
настраивается на его стороне, а локальные `GOOGLE_*` остаются пустыми.
После изменения работающей установки выполните проверку и применение по
[руководству конфигурации](configuration.md#изменение-работающего-сервера).

В Google Cloud настройте OAuth consent screen и создайте OAuth client типа **Web application**. Добавьте в **Authorized redirect URIs** точный адрес:

```text
https://mas.example.org/upstream/callback/01K5WZ00000000000000000001
```

Впишите Client ID и Client Secret в `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`.
Если интерфейс просит Authorized JavaScript origins, используйте
`https://mas.example.org`, без пути. В режиме Testing добавьте нужные
Google-аккаунты как test users; для остальных пользователей настройте публикацию
consent screen по правилам Google.
[Документация Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect).

## 5. Telegram

Этот раздел относится ко входу через Telegram на локальном MAS. Управляющий
Telegram-бот подключается отдельно и для установки не требуется.
Дальнейшие шаги применимы при `MAS_MODE=local`: используйте его фактический домен
вместо `mas.example.org`, реквизиты внесите в мастер или `settings/auth.env`.
При внешнем MAS настройте провайдер на нём; локальные `TELEGRAM_*` оставьте пустыми.
Применение изменений — по [руководству конфигурации](configuration.md#изменение-работающего-сервера).

В BotFather создайте или выберите своего бота и включите **OpenID Connect Login**. Используйте выданные для этого раздела Client ID и Client Secret, а не токен бота или реквизиты приложения Telegram API.

В **Redirect URIs** добавьте:

```text
https://mas.example.org/upstream/callback/01K5WZ00000000000000000002
```

В **Trusted Origins** добавьте:

```text
https://mas.example.org
```

Впишите `TELEGRAM_CLIENT_ID` и `TELEGRAM_CLIENT_SECRET` в env. Если нужен прокси, заполните:

```dotenv
SOCKS5_CONFIG=socks5://username:password@proxy.example.net:1080
```

Спецсимволы в имени и пароле прокси кодируйте как URL (`@` → `%40`, `:` → `%3A`,
`%` → `%25`). Прокси должен работать постоянно; он используется только для
входа через Telegram. [Документация Telegram OIDC](https://core.telegram.org/bots/telegram-login).

Вход через разные провайдеры сам по себе может создать разные Matrix-аккаунты. Чтобы добавить свободную Telegram-идентичность к существующему аккаунту Google, сначала войдите через Google в MAS, затем **в том же браузере** откройте:

```text
https://mas.example.org/upstream/authorize/01K5WZ00000000000000000002
```

Подтвердите связывание. Уже связанная с другим, в том числе удалённым, аккаунтом идентичность автоматически не переносится. Удаление Matrix-аккаунта не гарантирует освобождения его OAuth-привязки или Matrix ID.

## 6. Запуск и проверка

Если мастер уже завершил установку, повторять `start` не нужно: начните с
`status` и `check`. При настройке через CLI после `config init` и заполнения
DNS, сетевых правил и настроек выполните:

```bash
sudo misbot start
sudo misbot status
sudo misbot check
```

Перед запуском можно отдельно выполнить `sudo misbot config preflight`:
команда проверяет систему, DNS, порты и прокси. При ошибке исправьте указанную
причину и повторите проверку. При конфликте порта используйте `sudo ss -lntup`,
сохранив доступ по SSH. При ошибке SOCKS5 исправьте реквизиты или отключите
необязательный Telegram, очистив оба его поля.

Первый запуск может занять несколько минут. При таймауте сообщение содержит
команду просмотра журналов и повторного запуска. Исправьте причину и повторите
`sudo misbot start`: существующие ключи и данные сохраняются.
Успех — `installation_running`, работающие службы в `status` и успешный `check`.
`status` также показывает загрузку CPU, RAM, swap, диск раздела установки и время
без перезагрузки. Отсутствующие измерения не считаются нулевой нагрузкой.

Для первого приглашения после CLI-установки выполните
`sudo misbot users invitation ensure`, затем `sudo misbot users invitation show`.
`ensure` создаёт или продолжает выдачу сохранённого первого кода; использованный,
истёкший или отозванный код не заменяет. Проверка состояния —
`sudo misbot users invitation status`, явная замена — `sudo misbot users invitation new`.
Передайте код лично; не публикуйте его в журналах или на главной странице.
В UI выдача предлагается после запуска.

При отказе S3 перед запуском сохраняйте данные и конфигурацию. Исправьте доступ
к хранилищу и повторите указанную в сообщении команду. Локальное хранение
можно выбрать только до первого успешного запуска с S3; действующее
хранилище этой командой не отключается.
Порядок продолжения переноса — в [storage.md](storage.md).

Откройте `https://web.example.org`. В Element X на телефоне укажите
**example.org**. Для нового пользователя создайте аккаунт с кодом приглашения,
затем войдите в клиент. Проверьте выбранные способы входа, зашифрованный чат,
фото и звонок между двумя устройствами, желательно между Wi-Fi и мобильной
сетью. Автоматический `check` проверяет доступность служб; вход и звонок нужно
проверить самостоятельно.

Администратор — `@matrix-admin:example.org`. Его автоматически созданный пароль и адрес админки доступны root:

```bash
sudo misbot credentials admin show
```

Войдите на `https://admin.example.org` этой учётной записью с логином и паролем.
Обычная Google/Telegram-учётная запись не получает административные права
автоматически. Сохраните пароль в своём менеджере паролей.

После перезагрузки VPS службы запускаются автоматически. Сертификаты
обновляются автоматически; во время их обновления возможен краткий перерыв
звонков. После намеренной остановки вернитесь к работе через `sudo misbot start`,
затем `sudo misbot check`.

### Реферальный бот

Аккаунт **`@referral-bot:example.org`**, имя **«Реферальный бот»**, создаётся автоматически при первом успешном запуске. Откройте с ним личный зашифрованный чат в Element X. Для первого приглашения войдите первоначальным администратором; дальше кодами могут управлять все активные пользователи этой установки.

- `пригласить` — создать приглашение; сообщение можно целиком переслать другу.
- `пригласить Для Антона` — создать код с названием, которое видно только создателю.
- `токены` или `токены 20` — свои коды; отозванные и истёкшие неиспользованные скрыты, использованные остаются.
- `отозвать` — нумерованный список; ответьте номером. `ещё` продолжает список, `отмена` или `0` отменяют выбор. Выбор действует 15 минут. `отозвать ID` отзывает только собственный код.
- `помощь` — команды, аргументы, срок и лимит регистраций. Старые slash-команды показывают эту справку.

Отдельная [административная панель](admin-panel.md) `@admin-panel:example.org`
управляет [федерацией и заявками Misbot](federation.md). В обновлённых установках
сохраняется прежний адрес бота, в том числе `@federation-bot:example.org`.
Напишите `помощь`, затем выберите `федерация`. Доступ имеют первоначальный
администратор и явно добавленные местные администраторы с действующими серверными
правами; роль в комнате не подходит. В SSH UI выберите раздел
«федерация/бот/заявки», CLI: `sudo misbot federation help`.

Коды выводятся моноширинным шрифтом, срок — в МСК. Бот принимает команды только
в личных зашифрованных чатах с активными местными аккаунтами; кодами другого
пользователя управлять нельзя. Он не управляет федерацией или пользователями.
Управляющий Telegram-бот необязателен и подключается по отдельной инструкции:
`telegram-bot/README.md` в архиве, `bots/telegram/README.md` в репозитории.

Ответ на `пригласить` содержит название сервера, код, фактический лимит регистраций
и срок, затем отдельные шаги для телефона и компьютера. В Element X нужно указать
Matrix `server_name`; ссылка на сайт ведёт к загрузке клиента, ссылка «веб-чат» —
к браузерному клиенту. Название берётся из `SITE_NAME` (пустое значение — домен).
Текст для пересылки не содержит личного названия кода и команд управления им.
В конфигурации runtime `config/referral-bot.json` поля `site_name`, `site_url` и
`web_url` задают название и публичные HTTPS-ссылки. Обычная установка заполняет их
при генерации; подключённая Compose-установка — при включении компонентов из
настроек сайта и feature plan. Старые конфигурации без этих полей поддерживаются:
используются `server_name`, `https://<server_name>/` и `https://web.<server_name>`.

Приглашения, названия и диалоги сохраняются при повторном запуске и перезагрузке.
При пропаже сохранённых данных бота восстановите их из резервной копии.

## 7. Файлы и обслуживание

[Краткая памятка и диагностика](administration.md) содержат команды, ожидаемые
результаты, действия при ошибках и ссылки на сложные операции.
[Пользователи и сеансы MAS](users.md) описывает блокировку, разблокировку и отзыв
сеансов с проверкой результата и действиями при ошибках.

| Путь относительно `/opt/matrix-stack` | Содержимое |
|---|---|
| `settings/` | Пользовательские настройки; см. [конфигурацию](configuration.md) |
| `secrets/`, `config/` | Закрытые служебные настройки, пароли и ключи; вручную не менять |
| `data/` | Базы, медиа, ключи и данные ботов |
| `stages/` | Краткие результаты этапов без паролей |
| `backups/` | Полные приватные копии |

Основной каталог закрыт от обычных пользователей.

Команды:

```bash
# Сохранить копию перед изменением настроек
sudo misbot backup create
sudo nano /opt/matrix-stack/settings/server.env
# Проверить и применить с проверенной копией
sudo misbot config validate
sudo misbot config apply
# Сгенерировать файлы и подготовить образы без перезапуска
sudo misbot config generate
# Остановить, сохранив данные
sudo misbot stop
```

`generate` подготавливает конфигурацию и ресурсы: скачивает недостающие закреплённые Docker-образы, собирает образы ботов и записывает файлы на диске. Это не просмотр и не проверка без изменений; для проверки настроек используйте `sudo misbot config validate`. Перезапуск службы может применить сгенерированные файлы. Для диагностики контейнеров:

```bash
sudo docker compose --project-directory /opt/matrix-stack -f /opt/matrix-stack/compose.yaml logs --tail=100 mas synapse
```

Журналы приложений могут содержать личные данные: просматривайте их приватно.
Не удаляйте `secrets/`, `config/` или `data/` ради повторного запуска.
Утраченные ключи и базы нужно восстанавливать из копии.

При сообщении `Another installer operation is running` проверьте `status`,
дождитесь завершения операции и повторите команду. Не удаляйте её lock-файл.
Подробности — в [разделе о журналах и диагностике](administration.md#журналы-и-диагностика).

## 8. Резервная копия и восстановление

Полный состав копии, команды шифрования и внешнего S3, скачивание на новой машине,
ошибки и условия восстановления зашифрованной истории описаны в
[backup.md](backup.md). Проверяйте пригодность копии для своей установки отдельно.

```bash
sudo misbot backup create
sudo misbot backup verify
```

Копирование кратко останавливает необходимые службы, сохраняет базы, настройки,
ключи, медиа и данные ботов, затем возвращает ранее работавшие службы к работе.
Архив лежит в `backups/`, `latest.tar.gz` указывает на последнюю копию.
`backup verify` проверяет целостность копии и восстановление баз, сохраняя
рабочие данные. Полное пробное восстановление выполняйте на отдельном VPS.

Локальная копия содержит секреты и **не зашифрована**. Храните её вне VPS
в защищённом хранилище; переносите по SSH и ограничивайте доступ.
Шифрованные внешние копии и расписание — в
[инструкции резервного копирования](backup.md#регулярные-копии-через-systemd).
Ключ восстановления и реквизиты Vault сохраняйте отдельно по инструкции.

Если неудачная выгрузка S3 сообщает отказ очистки, используйте
`sudo misbot backup external cleanup` с исходными `--config` и `--catalog`
по [инструкции резервного копирования](backup.md).
Она запрашивает удаление только непроверенного объекта этой попытки, сохраняя
локальные данные и прежние проверенные копии.

Ниже показаны проба и перенос установки с **локальной PostgreSQL** на пустой VPS
с тем же доменом. Для внешней PostgreSQL используйте `restore-local`, описанный
ниже. При внешнем MAS сначала выполните
[отдельные условия сохранения его состояния](backup.md#копии-при-внешнем-mas):
архив Misbot не содержит его базы, а активация требует дополнительного
`--external-mas-confirm preserved-state`.

Сначала выполните пробу без смены DNS и запуска второго чата. В примере для неё
выделен `/opt/matrix-restore-test`, для окончательного переноса — другой пустой
каталог `/opt/matrix-stack`.

1. На исходном VPS выполните `sudo misbot backup create`,
   `sudo misbot backup verify` и запишите SHA256 из строки
   `consistent_backup`. Передайте архив по SSH в закрытый каталог целевой машины.
   Контрольная сумма должна прийти с источника, а не вычисляться только после передачи.
2. На целевом VPS из каталога нового комплекта выполните команду ниже. Замените
   имя архива, `SHA256_С_ИСТОЧНИКА` и пример IPv4 реальными значениями. Каталог
   назначения должен быть пустым. `init` перед восстановлением не требуется.

```bash
sudo python3 misbot.py backup restore --archive /root/matrix-backup.tar.gz --sha256 'SHA256_С_ИСТОЧНИКА' --public-ip 203.0.113.20 --directory /opt/matrix-restore-test
```

Команда проверяет архив и восстанавливает данные без запуска чата и ботов.
Ожидается `restore_staged`. При ошибке контрольной суммы повторно передайте
исходный архив. При прерывании повторите **ту же команду с тем же архивом**.
Для копии архива в каталоге назначения нужно дополнительное место размером
с архив. Затем из каталога нового проверенного комплекта выполните
`sudo python3 misbot.py --directory /opt/matrix-restore-test backup verify`.
На чистом VPS системная команда `misbot` ещё не зарегистрирована: до активации
проверки и восстановление выполняйте через `sudo python3 misbot.py`, явно
задавая каталог назначения.

Если финальное восстановление будет на том же VPS, после проверки пробы
освободите её Compose-контейнеры и сеть, сохранив файлы:
`sudo bash /opt/matrix-restore-test/install.sh down`. Другой каталог сам по себе
не изолирует Compose project и имена контейнеров. Пробный экземпляр не активируйте.

3. На источнике текущим установщиком выполните `sudo misbot backup move export`,
   затем `sudo misbot backup verify`. Успех — `migration_source_frozen` с путём
   финального архива; исходный сервер остаётся остановленным. При отказе
   сохраняйте источник, проверьте `status` и повторите экспорт после
   исправления доступа к хранилищу.
   Подробный путь внешней защищённой копии и отмены — [backup.md](backup.md#финальная-копия-перед-переносом).
   После обрыва SSH или прерывания выполните `sudo misbot status` и следуйте
   указанной команде продолжения, дождавшись завершения активной операции.
   Передайте финальный архив и его контрольную сумму на целевую машину.
   Восстановите именно финальную копию в **новый пустой** `/opt/matrix-stack`:

```bash
sudo python3 misbot.py backup restore --archive /root/matrix-final-backup.tar.gz --sha256 'SHA256_ФИНАЛЬНОГО_АРХИВА_С_ИСТОЧНИКА' --public-ip 203.0.113.20 --directory /opt/matrix-stack
sudo python3 misbot.py --directory /opt/matrix-stack backup verify
```

Новый архив нельзя применить поверх `/opt/matrix-restore-test`: checkpoint
привязан к архиву, SHA256, IPv4 и способу восстановления БД. Повтор той же команды
предназначен только для продолжения той же операции.

Переключите A-записи управляемых имён на целевой IPv4, проверьте отсутствие AAAA
и дождитесь обновления DNS. DNS отдельного внешнего MAS не переносится.
Две независимые пишущие установки недопустимы. Из каталога проверенного комплекта:

```bash
sudo python3 misbot.py --directory /opt/matrix-stack backup activate --confirm source-stopped
sudo misbot check
```

`source-stopped` подтверждает, что исходный сервер остановлен;
команда сама не управляет другой машиной. Если запуск при активации завершился
ошибкой, службы назначения останавливаются, включая PostgreSQL. Исправьте причину,
повторите исходную команду восстановления с теми же параметрами, чтобы вернуть
PostgreSQL без повторного импорта готовых БД, затем повторите активацию. После запуска
комплект регистрирует системную команду `misbot`. Проверьте вход, старые вложения,
зашифрованные сообщения, федерацию и звонки. Если системная команда недоступна
или активация ещё не завершилась, продолжайте проверки через проверенный
распакованный комплект с явным `--directory`, сохраняя данные и ключи; подробности — в
[описании системной команды](cli.md).

До активации восстановленный чат остаётся остановленным. Для пробного
восстановления менять DNS не нужно. Для реального переключения сначала
остановите источник, выполните проверки копии и пройдите маршрут выше.

Если архив создан с внешней PostgreSQL, используйте явное
восстановление включённых в копию БД в новую локальную PostgreSQL 18:

```bash
sudo python3 misbot.py backup restore-local --archive /root/matrix-backup.tar.gz --sha256 'SHA256_С_ИСТОЧНИКА' --public-ip 203.0.113.20 --directory /opt/matrix-stack
```

Исходная внешняя БД при этом не подключается и не изменяется. Остальные проверки,
ограничения до активации и порядок запуска те же. При прерывании повторяйте
ту же команду `backup restore-local`, не меняя архив, IP и каталог назначения.
Подробности и ограничения — в
[инструкции резервного копирования](backup.md#внешняя-postgresql-восстановление-в-локальную).
Восстановление в другой внешний кластер остаётся неподдержанным.
Серверная копия не содержит ключей E2EE из клиентских устройств: для зашифрованной
истории пользователю нужны его проверенное устройство или ключ восстановления
и доступная резервная копия клиентских ключей.

Восстанавливайте настройки, ключи и данные ботов вместе со всеми включёнными
в копию базами. Внешний MAS сохраняется и восстанавливается отдельно.
Не удаляйте ключи ради повторного запуска.

Восстановление сохраняет исходный домен сервера. Импорт базы другой установки
с другим доменом не поддерживается. Для переноса существующего сервера нужен
отдельный план с сохранением ключей и идентификаторов.

## 9. Версии и границы возможностей

Версии компонентов зафиксированы в [versions.json](versions.json).
Обновляйте сервер через Misbot с резервной копией и проверкой совместимости;
смена основной версии PostgreSQL требует отдельной миграции.

В браузере используется Element Web, на телефоне — Element X. Для других
клиентов нужна поддержка OAuth; старые приложения могут не поддерживать вход.
Подписи фотографий, альбомы и сжатие фото/видео зависят от клиента.
Ключ восстановления зашифрованной истории сохраните отдельно: вход через
Google/Telegram его не заменяет. Восстановление пароля по email недоступно
без отдельной настройки почты.

Для своей установки выполните клиентские проверки из раздела 6, пробное
восстановление копии и проверки выбранных внешних сервисов. Доступность служб
и локальные тесты не подтверждают регистрацию, вход, зашифрованную переписку,
федерацию и звонки в конкретной конфигурации.

## 10. Обновление

`misbot version` показывает версию установленного комплекта. У локальной
сборки она содержит номер, например `Misbot 1.2.0-build.123`;
у опубликованного релиза — `Misbot 1.2.0`. Предварительные сборки сохраняют
суффикс в имени компактного архива. Окончательный релиз считается новее
любой предварительной сборки с тем же номером версии. Проверка нового релиза:
`sudo misbot update check`; загрузка и применение готового комплекта:
`sudo misbot update latest`. Команда выбирает последний стабильный релиз и
проверяет допустимость перехода; при несовместимости обновление отклоняется,
другой кандидат автоматически не подбирается.
В [административной панели](admin-panel.md)
доступна команда `обновить` с подтверждением и результатом операции.
`sudo python3 misbot.py update` применяет распакованный комплект, из которого
запущена команда. Справка: `python3 misbot.py update --help`; она ничего не меняет.
Загрузка из GitHub выполняется только явной командой `update latest`.

Перед обновлением Misbot создаёт и проверяет резервную копию. Обновление
сохраняет домен, ключи, настройки, историю и отметки доставки. Подготовка данных
выполняется автоматически, в том числе при пропуске промежуточных релизов;
повторный запуск сохраняет уже выполненные шаги. Подробности и ограничения —
в [миграциях данных](data-migrations.md). Обновление может потребовать перерыва
в работе сервера.

Обновление переносимой установки заново формирует регистрацию MatrixRTC
для закреплённой версии Synapse, сохраняя токены приложения и ключ LiveKit.
LiveKit создаёт комнаты через службу выдачи токенов после проверки доступа;
автоматическое создание комнаты при подключении клиента отключено.

Поддерживается обновление совместимого переносимого комплекта с теми же
версиями компонентов и переход Synapse 1.161.0 → 1.162.0 при прежних версиях
остальных компонентов. Для старых установок без `SHA256SUMS` нужен отдельный
план импорта. Произвольная смена версий компонентов, понижение версии и
выборочная замена файлов не поддерживаются.

На VPS распакуйте новый доверенный комплект в отдельный каталог, проверьте его
`sha256sum -c SHA256SUMS` и из этого каталога выполните:

```bash
sudo python3 misbot.py update
sudo misbot check
```

Misbot выбирает установку рядом с выполняемой командой, затем сохранённый
системный каталог, затем проверенный `/opt/matrix-stack`. Если установка
не найдена, в терминале будет предложено ввести абсолютный путь; без терминала
команда покажет, как повторить запуск с `--directory /путь/к/установке`.
Недействительная или небезопасная сохранённая установка останавливает обновление;
другая установка вместо неё автоматически не выбирается. Явный `--directory`
имеет приоритет. Для системной команды укажите новый комплект:
`sudo misbot update --source /root/matrix-installer`. Подходит и полный, и компактный
комплект: внутренний каталог выбирается автоматически. Прежняя форма
`update apply --directory PATH --source PATH` также поддерживается.

Если не хватает места, расширьте диск либо удалите посторонние файлы,
сохранив данные Matrix, ключи и проверенные копии, затем повторите обновление.
Успех — `release_applied` с версией нового комплекта. При ошибке запуска Misbot
пытается вернуть прежнюю версию; результат указан как `rollback healthy`.

После прерывания или неудачного возврата прежней версии проверьте `status`
и выполните восстановление через доверенный распакованный комплект:

```bash
sudo misbot update recover --directory /opt/matrix-stack --source /root/matrix-installer
sudo misbot check
```

Ожидается `update_recovered` прежней версии и `healthy True`. После этого
можно повторить обновление. Если службы не запускаются, исправьте указанную
причину и повторите восстановление. Сохраните данные и служебные файлы
незавершённой операции.

Автоматический возврат прежней версии программы не возвращает прежнюю схему
базы данных. Если совместимость не подтверждена, сохраните данные и восстановите
полную копию в пустом каталоге по [инструкции резервного копирования](backup.md).
Смена основной версии PostgreSQL этим обновлением не поддерживается.

## 11. Панель, приветствия и полное удаление

[Панель администратора](admin-panel.md) `@admin-panel` доступна первоначальному
администратору и явно добавленным местным администраторам с действующими правами.
Она предлагает уведомления, обновление из GitHub Releases, резервные копии,
настройку приветствия `@server-guide`, рассылки с подтверждением и статистику.
При обновлении сохраняется прежнее имя бота. Настройку копий, восстановление
и перенос выполняйте через SSH.
Команда панели `изменить приветствие`, затем новый текст меняет приветствие
для будущих регистраций. Обновление заменяет только известный старый штатный
шаблон; пользовательский текст и очередь доставки сохраняются.

`sudo misbot remove` работает после `init`, при незавершённой установке и на
работающем сервере этого комплекта. В интерактивном терминале выберите категории
локальных данных, каталоги S3, внешние базы, созданные установщиком, и Vault.
Затем подтвердите
итоговый список и точную фразу с доменом. Перед финальным подтверждением данные
не удаляются. В выбранных каталогах S3 удаляются также старые версии объектов
и незавершённые загрузки; бакет и остальные каталоги сохраняются. Для отдельного
профиля копий можно передать `--backup-config /root/misbot-backup-s3.env`.

Удаление сначала останавливает службы, затем очищает выбранные внешние ресурсы
и локальные данные. При отказе провайдера повторите ту же команду после
исправления доступа; прежний план продолжается после нового подтверждения.
При ошибке выводятся этап и безопасное описание причины; сырые ответы служб и
credentials не выводятся. Подтверждённые шаги пропускаются, незавершённый шаг
повторяется. Пустой список `completed` означает, что ни один шаг не подтверждён;
он не доказывает отсутствие частичных действий внутри шага.
Удаление и локальные копии не требуют пакета шифрования `cryptography`.
На старом комплекте, где `remove` останавливается до первого шага из-за его
отсутствия, установите `python3-cryptography` из пакетов системы и повторите
ту же команду. Существующий журнал сохраняет выбранный план удаления.
Исходники утилиты и системная команда остаются. После полного удаления
`sudo misbot ui` предлагает создать новый сервер, восстановить копию или войти
в меню. Новая установка начинается только после выбора мастера.
При удалении секретов удаляются также текущий и сохранённые прежние приватные
черновики этой установки; черновики других установок сохраняются.
При частичном выборе сохранённые файлы остаются, но запуск сервера блокируется;
для новой установки сначала завершите полное удаление.

Ручное удаление каталога не останавливает Docker-контейнеры и системные службы;
системная команда и приватный черновик мастера тоже могут остаться.
Если каталог ещё не создан или в нём нет установки, `remove` указывает выбранный
путь и предлагает отдельные команды черновика. Создавать установку ради удаления
не нужно. Из распакованного комплекта: `sudo python3 misbot.py config draft show`;
сброс текущего черновика: `sudo python3 misbot.py config draft reset --confirm discard-draft`.
Другой каталог выбирается через `--directory /абсолютный/путь`. Сброс черновика
не удаляет сервер, ключи, данные, checkpoints или архив прежних черновиков.
Если `installation.json` больше нет, черновик этапа проверки не запускает
`check`: мастер предлагает пройти настройки с начала или создать новый черновик,
сохранив прежний отдельно. Для запуска из удалённой установки нужен новый
проверенный распакованный комплект. Оставшиеся файлы автоматически не перезаписываются.

Выгрузки и секретные файлы, вручную сохранённые вне установки, копии на других
Matrix-серверах и устройствах пользователей не входят в локальную область удаления.
Удаление не удаляет VPS, домен, аккаунт у S3-провайдера или Docker как системный пакет.
