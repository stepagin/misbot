# Первый запуск и первые дни

Это маршрут для владельца небольшого сообщества, который управляет доменом
и может подключиться к VPS по SSH. Misbot подготавливает Matrix-сервер,
но выбор домена, доступы и проверка общения остаются за владельцем.
Подробные параметры и команды находятся в [руководстве установки](../installer/README.md).

В примерах `example.org` — вымышленный основной домен,
`/opt/matrix-stack` — каталог установки. Замените их своими значениями.

## 1. Выберите сервер и окончательный домен

Подготовьте чистый VPS, доступ root/sudo и управление DNS. Проверьте
[требования к системе и сети](../installer/README.md#1-что-подготовить).
На машине с уже работающим Matrix начните с
[подключения существующего Compose-стека](../installer/existing-compose.md).

Основной домен станет частью адресов `@имя:example.org`.
Его нужно сохранить при обновлении и переезде: смена Matrix `server_name`
готовой установки не поддерживается.

Для первого запуска подходят локальная PostgreSQL, локальные медиа и вход
по паролю. Google/Telegram OAuth и S3 подключайте, когда их реквизиты готовы.
Управляющий Telegram-бот настраивается отдельно от входа через Telegram.

**Результат:** выбран постоянный домен, доступен подходящий VPS и есть доступ
к DNS и SSH, который останется у администратора после установки.

## 2. Откройте мастер и подготовьте DNS

Используйте [запуск через SSH](../installer/README.md#быстрый-запуск-через-ssh).
Он доступен для опубликованного релиза с asset `install.sh`.
Если этого файла нет, скачайте официальный комплект и контрольные суммы
из выбранного релиза, проверьте и распакуйте его по
[ручной инструкции](../installer/README.md#3-загрузка-и-создание-файлов).
Из каталога проверенного комплекта откройте мастер:

```bash
sudo python3 misbot.py ui
```

Мастер покажет DNS-записи и проверит их. Создайте записи у своего DNS-провайдера,
отключите DNS proxy и откройте необходимые порты по
[таблице DNS и портов](../installer/README.md#2-dns-и-сетевые-порты).
Не закрывайте SSH. Основная схема использует IPv4: уберите AAAA для используемых
имён и отключите HTTP/CDN proxy по таблице установки.

Введите домен без `https://`, пути и порта. Выберите пустой каталог установки,
проверьте итоговые параметры и выберите **применить**.
**Сохранить и выйти** сохраняет черновик для продолжения.
Работа с полями и повтором описана в [руководстве мастера](../installer/configuration.md).

**Результат:** DNS соответствует выбранному серверу, настройки проверены,
установка запущена. Сохранённый черновик сам по себе не означает готовность сервера.

## 3. Проверьте запуск и сохраните доступ администратора

После завершения мастера выполните:

```bash
sudo misbot status
sudo misbot check
sudo misbot credentials admin show
```

`status` показывает службы и незавершённые операции, `check` проверяет
их доступность. Последняя команда показывает первоначальный административный
аккаунт и реквизиты только в приватном root-терминале. Сохраните пароль
в менеджере паролей и войдите в Element Admin по указанному адресу.

При обрыве SSH подключитесь снова и начните с `sudo misbot status`.
Дождитесь активной операции и выполните предложенное продолжение.
Если первоначальный запуск не завершён и отдельное recovery не требуется,
повторите `sudo misbot start`, затем `sudo misbot check`.
Данные и ключи сохраняются; подробности — в
[ежедневном управлении](../installer/administration.md).

**Результат:** автоматические проверки успешны, административный вход работает,
реквизиты сохранены независимо от VPS.

## 4. Пригласите первого участника и проверьте общение

Мастер предлагает первый код регистрации после запуска. Для установки через CLI:

```bash
sudo misbot users invitation ensure
sudo misbot users invitation status
sudo misbot users invitation show
```

`ensure` создаёт или продолжает первое приглашение; `show` показывает код
в приватном root-терминале. Использованный или истёкший код не заменяется
автоматически. Управление приглашениями — в
[настройках регистрации](../installer/configuration.md#администратор-и-первый-токен).

Передайте код лично. Новый пользователь открывает регистрацию, вводит код,
создаёт аккаунт и входит в клиент. В Element X адрес сервера — `example.org`;
браузерный чат находится на `https://web.example.org`.
Существующий пользователь сразу входит в свой аккаунт.

Проверьте каждый включённый способ входа, зашифрованный чат, вложение и звонок
между двумя устройствами, включая Wi-Fi и мобильную сеть. Участник настраивает
восстановление своих клиентских ключей и самостоятельно хранит свой recovery key
в менеджере паролей. Администратор проверяет этот сценарий на своём тестовом аккаунте.
Автоматический `check` не заменяет [клиентскую приёмку](../deployment/requirements.md).

**Результат:** приглашённый участник зарегистрирован, сообщения и вложения читаются,
звонок проходит в нужных сетях; клиентские ключи можно восстановить.

## 5. Подготовьте копии до регулярного использования

Создайте локальную согласованную копию и проверьте её:

```bash
sudo misbot backup create
sudo misbot backup verify
```

Локальный архив не защищает от потери VPS. Подготовьте независимое внешнее
хранилище, создайте зашифрованную копию и пробно восстановите её по
[руководству резервного копирования](../installer/backup.md).
Храните ключ расшифрования отдельно от сервера и копии.
Если MAS внешний, его состояние нужно сохранять отдельно.

Настройте [расписание копий](../installer/backup.md#регулярные-копии-через-systemd),
проверьте реальный запуск таймера и контролируйте свободное место.
Автоматическое удаление старых копий не предусмотрено.

**Результат:** есть доступная вне VPS проверенная копия, независимый ключ,
проверенный маршрут восстановления и работающее расписание.

## Дальнейшая работа

Для ежедневного управления откройте [Matrix-панель](../installer/admin-panel.md)
или [SSH-меню](../installer/cli.md). При необходимости добавьте личный аккаунт
администратора по [руководству пользователей](../installer/users.md#добавить-личного-администратора).
Включение OAuth не выдаёт административные права автоматически.

Перед обновлением изучите [ограничения выпуска](../installer/release-notes.md)
и [процедуру обновления](../installer/README.md#10-обновление).
Для переноса используйте [маршрут с сохранением identity](../deployment/migration.md).
Ответы на частые вопросы находятся в [FAQ](faq.md), остальные руководства —
в [каталоге документации](README.md).
