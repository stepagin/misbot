# Telegram: управление через Misbot

Telegram-бот показывает состояние сервера своей установки и управляет им
в личном чате. Перед работой войдите через страницу авторизации сервера (MAS).
Меню управления доступно только серверным администраторам; обычному участнику
доступны его приглашения.

Один экземпляр управляющего Telegram-бота привязан ровно к одному серверу.
Домен закрепляется в данных worker и не выбирается из чата. Для смены Telegram-аккаунта
откройте этого же бота с нового аккаунта и войдите в прежний аккаунт MAS.
После успешного входа старый Telegram-аккаунт теряет доступ и подписку на уведомления;
его подтверждения отменяются, приглашения и результаты операций доступны новому аккаунту.
Это работает также после `/logout` и перезапуска бота. Другой аккаунт MAS получает
только свои данные и свои текущие права; Telegram username не используется для выдачи прав.

После входа через MAS кнопка «Проверить вход» проверяет подтверждение.
В приглашении показаны код, срок в МСК, число регистраций и состояние кода.
Код можно скопировать отдельной кнопкой; рядом доступны ссылки скачивания
Element X для Android и iPhone. В ответах о проверке служб состояние
обозначено словами «Проверено» и «Нужна проверка». Выполняющаяся операция
предлагает проверить результат; сообщение об успехе приходит после подтверждения
backend.

## Меню

На главном экране администратора находятся статистика, статус служб,
проверка сервера и федерация. Кнопки появляются по возможностям установки.
В «Обслуживании» сгруппированы запуск, остановка, перезапуск, резервные копии
и обновления. В «Ещё» находятся приглашения, хранилища и компоненты.
Проверка работающих служб и адресов не подтверждает вход в клиент,
зашифрованную переписку или звонки.

Переходы обновляют одну навигационную карточку. Если её удалили, бот создаёт
новую. Коды приглашений, уведомления и результаты операций остаются отдельными
сообщениями. Проверка результата обновляет карточку соответствующей операции.
История автоматически не удаляется. Старые кнопки панели предлагают открыть
актуальное меню; полномочия повторно проверяются перед действием.

Федерация содержит отдельные списки входящих, исходящих и отклонённых заявок.
Приглашение сервера отправляется через Misbot API и действует 30 дней.
Одному серверу доступно одно актуальное приглашение; отправка ограничена
одним приглашением в минуту. Входящую заявку можно принять или отклонить,
исходящую — отозвать. При отказе другая сторона получает уведомление и может
обратиться повторно. Закрытые записи можно очистить. Уже подключённым серверам
новые заявки недоступны.

В настройках федерации можно включить или выключить Misbot API. Значение
сохраняется после перезагрузки до следующего переключения. Выключение
приёма API не удаляет действующие правила Matrix-федерации. Неподтверждённая
доставка отображается отдельно от отказа другой стороны.
Уведомления продолжают приходить ранее привязанному аккаунту после истечения
входа в бота, пока MAS подтверждает его действующие административные права.
Команды требуют нового входа. `/logout` отключает также доставку уведомлений.

## Реквизиты и адреса

Приватный `worker.json` содержит `token` из BotFather (формат `числа:строка`),
`username` без `@`, `client_id` — числовой ID Telegram-бота — и `server_name`.
Секрет Telegram Login настраивается отдельно. Для прокси добавьте `proxy`, например
`socks5h://proxy.example.org:1080`. SOCKS требует Python-пакета PySocks.
Не включайте секретные файлы в Git или журналы.

В `bot-config.json` управляющей службы `servers` содержит ровно одну запись:
Matrix `server_name` с независимым `mas_url`, `synapse_url` и служебными
`client_id`/`client_secret` **MAS**. Адрес MAS может отличаться от Matrix-домена.
Служебный клиент должен поддерживать device authorization и быть перечислен
в MAS `policy.data.admin_clients`; сохраняйте существующие clients и issuer.
Рядом нужны `bot-policy.json` и закрытый каталог `data/` для данных бота.
В `bot-policy.json` должен быть тот же единственный сервер. `server_name` в
`worker.json` обязателен и должен совпадать с ним. Несовпадение сохранённой привязки
останавливает worker без перезаписи данных; для переезда сохраняйте прежний домен
и состояние бота. Один token BotFather используется только одним worker этой установки.

## Команды управления

Управление включается явно: `stack_root` и
`management_actions: ["status", "check", "start", "stop", "storage", "storage_connect", "backup", "backup_verify"]` в серверном
`bot-config.json`. Для подключённого управления доступны также чтение статистики
и проверка обновлений; перезапуск разрешён при подключённых запуске и остановке.
Автоматическое применение обновления обычной установки включается отдельно действием `update`.
В Telegram: `/status`, `/check`, `/statistics`, `/storage`, `/start_services`, `/stop_services`,
`/backup`, `/backup_verify`; перезапуск и обновления открываются в «Обслуживании».
Общий backend поддерживает обычные и подключённые установки; доступность действий
задаётся разрешениями и режимом установки. Обновление `existing-compose` выполняется
через SSH с проверенным source plan. Кнопка подключения S3 использует только заранее
заполненный root-only `.misbot/s3/media.env`. Запуск, остановка, подключение S3,
создание и проверка копии требуют одноразового подтверждения и выполняются в фоне; кнопка
показывает результат. Новые операции выполняются отдельными заданиями systemd;
результат сохраняется и доступен после перезапуска управляющей службы. Прерванные
задания автоматически не повторяются. Незавершённые задания прежнего runtime
сохраняются как interrupted; проверяйте их через SSH.

До включения общих компонентов задайте `federation_enabled: false`.
После `features enable` выберите `federation_backend: "misbot"` для управления
федерацией через Misbot. Одно подтверждение разрешает одну операцию.
Результат доступен через административного Matrix-бота и
`misbot federation operations`. Список разрешённых
серверов сохраняется при подключении. Пункт `components` добавляет кнопку
статуса компонентов и ссылки на веб-панель и сайт.
Приглашения не изменяют действующий режим регистрации.

## Запуск и проверка

На Linux worker можно запускать отдельным непривилегированным systemd user ID
с `LoadCredential=worker.json:/PRIVATE/worker.json`, собственным каталогом данных
и `MISBOT_CONTROL_SOCKET=/run/misbot-telegram/control.sock`. Аргументы worker:
`--config PATH --data PATH --health-address 127.0.0.1 --health-port 8088`.
Bridge запускается root с `--config PATH --socket-directory /run/misbot-telegram`.
Socket допускает worker UID/GID 10001; не выдавайте этому UID доступ к Docker.

Worker можно отдельно перенести в Compose с образом из `Dockerfile`; архив Misbot
содержит `telegram-bot/Dockerfile` и `requirements.txt`. Монтируются только собственный
`worker.json` readonly, каталог worker SQLite и readonly control socket. Управляющая
служба остаётся на хосте. Перед переключением остановите прежний worker и сохраните
согласованную SQLite; отключите его systemd unit, сохранив unit для восстановления.
После регистрации в инвентаризации Misbot управляет worker через общие команды,
а source update автоматически собирает и проверяет изменённый worker image с
сохранением прежнего pin для rollback. Изменение схемы SQLite требует отдельной
совместимой миграции; обновление образа не заменяет базу старым snapshot.

`/health` показывает готовность бота и управляющей службы.
После запуска проверьте реальный `/start`, вход через MAS и административное меню.
Локальные тесты: `python3 -m unittest discover -s bots/telegram/tests -p 'test_*.py'`.

Ответы Telegram сохраняются в локальной очереди до отправки. Постоянный отказ
получателя (например, блокировка бота) завершает доставку только этому чату.
Временные ошибки повторяются с задержкой, не более восьми попыток; ограничение
Telegram `retry_after` учитывается. Повтор отправки не запускает команду заново.
Новая навигационная карточка заменяет ожидающую старую, результаты операций
остаются отдельными сообщениями. После потерянного сетевого ответа Telegram
возможен повтор сообщения: API отправки не предоставляет ключ идемпотентности.
Сведения о последних 100 неуспешных доставках сохраняются без текста сообщений;
итог административной операции можно снова открыть в её карточке. Уведомления
проверяют действующую подписку перед повтором и отмечаются как `sent` или `failed`.
Готовность polling означает завершённый цикл обработки updates; ошибка
зависимости или незавершённая обработка не маскируется успешным `getUpdates`.
