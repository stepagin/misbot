# Инструкции для работы с репозиторием

## Назначение и структура

Этот каталог содержит публичный продукт Misbot: переносимый установщик Matrix и код двух ботов. Перед изменением поведения сверяйтесь с документацией соответствующей части проекта:

- `deployment/` — универсальные инструкции эксплуатации, сохранения identity и миграции; начните с `deployment/README.md`, `deployment/requirements.md` и `deployment/operations.md`. Инструмент зеркалирования истории и его тесты также находятся здесь.
- `installer/` — комплект для чистого сервера с произвольным доменом; установка и ограничения описаны в `installer/README.md`. `dist/matrix-installer.tar.gz` — локально собранный архив комплекта.
- `bots/telegram/` — Telegram-бот и общая управляющая служба.
- `bots/matrix-referral/` — единственные исходники Matrix-бота. `installer/referral-control/` хранит уникальные файлы управляющей службы; `installer/build.py` добавляет код обоих ботов из `bots/` в архив без дублирования в Git.

Планы, журналы, отчёты агента, свидетельства запусков и персональные серверные материалы ведите во внешнем локальном каталоге вне Git-проекта. Публичный продукт должен собираться без этого каталога. Проверяйте фактическую конфигурацию перед изменениями.

## Работа с изменениями

- Вносите небольшие изменения в исходники и документацию той части проекта, которой касается задача. Если меняется поведение установщика, проверьте, нужны ли обновление `installer/README.md`, тестов и собранного архива.
- Не меняйте Matrix `server_name`, домены, OAuth-привязки, ключи, базы данных и правила федерации как побочный эффект другой задачи. Для миграции и операций на рабочем сервере следуйте `deployment/migration.md` и `deployment/operations.md`.
- Не запускайте скрипты установки, миграции, восстановления или перезапуска на действующем сервере без прямого запроса на соответствующее действие. Локальное чтение и изолированные тесты допускаются.
- Секреты, ключи, дампы, резервные копии и приватные настройки держите вне Git-проекта в защищённом локальном каталоге или на сервере. Не включайте их содержимое в код, тестовые фикстуры, журналы и ответы. При работе с конфигурацией используйте вымышленные значения.
- Не считайте запуск изолированных тестов доказательством работоспособности OAuth, федерации или звонков на реальных клиентах; такие результаты фиксируйте отдельно.

## Локальные проверки

Из корня проекта запускайте проверки той части, которую изменили:

```bash
python3 -m unittest discover -s installer/tests -p 'test_*.py'
python3 -m unittest discover -s bots/telegram/tests -p 'test_*.py'
python3 -m unittest discover -s deployment/tests -p 'test_*.py'
(cd bots/matrix-referral && npm test)
python3 installer/build.py --check
```

Для изменённых shell-скриптов дополнительно используйте `bash -n <путь>`. Тесты `installer/tests/integration.py` и `installer/tests/oauth_internal.py` требуют отдельной оценки среды и не входят в обычный локальный набор.
